1. Introduction & Operating Modes (Standalone, Server, Client, Remote Control)

Germano AI è una suite autonoma progettata per proteggere la privacy, eliminare i dati personali sensibili (GDPR Art. 9 e 10) e consentire l'utilizzo sicuro di strumenti di Intelligenza Artificiale Cloud (come ChatGPT, Claude o Google Gemini) e ambienti di sviluppo CLI (Claude Code, OpenAI Codex CLI, Aider, OpenCode, Goose CLI) su qualsiasi computer con Windows 10 o 11, su Windows Server 2019 o successivo e nelle macchine virtuali (oltre che su macOS e Linux).

100% Locale, Standalone e Air-Gapped:

Germano AI include un runtime Python 3.11 embedded, tutte le librerie native C++ di sistema e 8 modelli di Intelligenza Artificiale pre-installati. Si installa con un solo file (germano-0.91.exe), che appena si apre mostra subito una schermata di avvio, chiede i permessi di amministratore (richiesta UAC) per consentire l'accesso dalla rete locale e alla fine apre Germano da solo, e funziona senza alcuna connessione a Internet per elaborare i documenti. Nessun dato personale lascia mai il tuo computer (con Chatbot e Agenti AI e con il Proxy API all'AI arrivano solo testi già anonimizzati); i soli collegamenti automatici sono l'aggiornamento silenzioso, come in Google Chrome, solo quando il PC è connesso e disattivabile (capitolo 13), e — solo se installi Antigravity CLI — la verifica periodica dei modelli del tuo account Google (capitolo 2).

Modalità operativa: Standalone, Server, Client

Alla prima apertura una finestra di benvenuto chiede come usare Germano su questo computer. Questa modalità è sempre modificabile in qualsiasi momento nelle Impostazioni (scheda Impostazioni › Modalità e rete, oppure il pulsante della modalità in alto, accanto allo stato del motore) e si applica subito, senza riavviare.

  • Standalone (predefinita): tutto gira al 100% su questo computer, in modo isolato. Germano non cerca server in rete e non risponde ai computer della rete: la Dashboard e il Proxy ascoltano solo su 127.0.0.1.
  • Server: Germano si mette in ascolto anche sulla rete locale, risponde al rilevamento automatico (UDP 8182) e offre agli altri computer e dispositivi il proprio motore di anonimizzazione, il Proxy e il Remote Control (da qualsiasi browser della rete, vedi i capitoli 2 e 11). Di base l'accesso dalla rete è libero; con la gestione utenti servono utente e password. Le Impostazioni mostrano gli indirizzi da aprire nel browser (http://<IP>:8181/remote). Con l'installer di Windows la regola del firewall (solo reti private e di dominio) è già creata; se esegui Germano dai sorgenti, al primo avvio Windows può chiedere di consentire Python sulle reti private: rispondi Consenti. Per un solo avvio la modalità si può imporre anche con la variabile d'ambiente GERMANO_MODE=server (utile negli script).
  • Client: all'avvio del motore Germano cerca in rete un Germano Server (oppure usa l'indirizzo indicato) e gli affida il calcolo dei modelli: questo computer non li carica in memoria. Al server vanno solo i testi e le immagini da analizzare; Vault, etichette, file e ripristino restano su questo computer. Dalla 0.90 fino a tre file della cartella input vengono elaborati insieme sul server e, all'aggancio e poi ogni 10 minuti, Germano mette alla prova il server con una frase di controllo con dati finti scelti a caso: se non li riconosce, il server non viene usato e nessun dato esce. Se il server ha la gestione utenti attiva, inserisci utente e password (Germano conserva solo la sessione). Se il server non risponde, o rifiuta l'accesso, nessun dato esce: Proxy e Chatbot e Agenti AI bloccano la richiesta e i documenti restano nella cartella input finché il server torna disponibile (in alternativa si può scegliere di usare il motore locale).
  • Server + Client: le due parti insieme. Un computer che delega il calcolo non condivide però il proprio motore con altri (niente catene).

Il cambio di modalità è possibile solo dal computer stesso, mai dalla rete; con "lock_settings": true l'amministratore la blocca. In config.json la scelta è salvata in operating_mode (standalone, server, client, server+client).

Suggerimenti al passaggio del mouse

Passando il mouse (o spostandosi con il tasto Tab) su pulsanti, cartelle, campi, filtri e indicatori compare una breve spiegazione. I suggerimenti sono attivi per impostazione predefinita e si disattivano nelle Impostazioni, sezione Interfaccia (enable_tooltips).

Sistemi supportati: Windows 10/11, Windows Server e macchine virtuali

  • Windows 10 e 11 a 64 bit.
  • Windows Server 2019, 2022 e 2025 (Standard e Datacenter), con Esperienza desktop per la finestra di Germano. Windows Server 2019 non include Microsoft Edge: senza Edge (o Chrome) Germano non usa Internet Explorer, che non sa mostrare la Dashboard, ma resta attivo come server senza finestra e indica gli indirizzi da aprire (anche da un altro computer); installando Microsoft Edge torna la sua finestra. Su Server Core, che non ha né Edge né il desktop, si usa la modalità senza finestra (capitolo 11).
  • Macchine virtuali: VMware (ESXi, Workstation), Hyper-V, Proxmox VE (KVM/QEMU), VirtualBox e le istanze cloud (AWS EC2, Azure, Google Compute Engine). Non serve una GPU: tutta la pipeline gira su CPU; il numero di thread si adatta alle vCPU e la precisione al processore (capitolo 9). Per l'accesso dalla rete la VM deve avere una scheda in modalità bridge (o uno switch virtuale esterno): dietro un NAT servono l'inoltro della porta TCP 8181 e l'indirizzo indicato a mano nei client, perché il rilevamento automatico (UDP 8182) non attraversa il NAT.
  • Nessuna installazione esterna: il programma contiene Python 3.11 e le DLL di Microsoft Visual C++ 2015-2022 (vcruntime140.dll, vcruntime140_1.dll, msvcp140.dll, msvcp140_1.dll, msvcp140_2.dll, vcomp140.dll per OpenMP, concrt140.dll e le altre): funziona anche su un Windows Server appena installato, senza ridistribuibili. Le altre DLL usate sono componenti standard di Windows.
  • I dati (Vault, cartelle di lavoro, stato) possono stare su dischi virtuali (vmdk, vhdx, qcow2) come su quelli fisici. Una cartella dati su una condivisione di rete (SMB o NFS) è protetta da un blocco del sistema operativo: un secondo Germano, anche da un altro computer, non può usarla insieme al primo (il Vault non può avere due scrittori).

Germano AI ships with an embedded Python 3.11 runtime, all native Visual C++ runtime libraries, and 8 pre-packaged local AI models. It installs from a single file (germano-0.91.exe), which shows a startup screen as soon as it opens, asks for administrator permission (UAC prompt) to allow access from the local network and opens Germano by itself at the end, and works with no Internet connection needed to process documents. No personal data ever leaves your machine (with the Chatbot & AI Agents and with the API Proxy, the AI only receives already anonymized text); the only automatic connections are the silent update, as in Google Chrome, only when the PC is online, and it can be turned off (chapter 13), and — only if you install Antigravity CLI — the periodic check of your Google account's models (chapter 2).

Operating mode: Standalone, Server, Client

On the first launch a welcome dialog asks how to use Germano on this computer. The mode can always be changed at any time in the Settings (the Settings › Mode & network tab, or the mode button at the top, next to the engine status) and applies immediately, without restarting.

  • Standalone (default): everything runs 100% on this computer, isolated. Germano does not search the network for servers and does not answer the computers on the network: the Dashboard and the proxy only listen on 127.0.0.1.
  • Server: Germano also listens on the local network, answers the auto-discovery (UDP 8182) and offers the other computers and devices its anonymization engine, the proxy and the Remote Control (from any browser on the network, see chapters 2 and 11). By default network access is open; with user management a user name and password are required. The Settings show the addresses to open in the browser (http://<IP>:8181/remote). With the Windows installer the firewall rule (private and domain networks only) is already in place; when running Germano from source, Windows may ask on first start to allow Python on private networks: answer Allow. For a single run the mode can also be forced with the environment variable GERMANO_MODE=server (useful in scripts).
  • Client: when the engine starts, Germano looks for a Germano Server on the network (or uses the address entered) and hands it the model computation: this computer does not load the models in memory. Only the texts and images to analyze go to the server; Vault, tags, files and restoration stay on this computer. Since 0.90 up to three input folder files are processed together on the server and, when connecting and then every 10 minutes, Germano tests the server with a control sentence containing randomly chosen fake data: if it does not recognize them, the server is not used and no data leaves. If the server has user management enabled, enter user name and password (Germano keeps only the session). If the server does not answer, or refuses access, no data leaves: the proxy and the Chatbot & AI Agents block the request and documents stay in the input folder until the server is back (alternatively you can choose to use the local engine).
  • Server + Client: both parts together. A computer that delegates its computation does not share its own engine with others (no chains).

The mode can only be changed from the computer itself, never from the network; with "lock_settings": true the administrator locks it. In config.json the choice is saved in operating_mode (standalone, server, client, server+client).

Main features

Germano AI is a complete document anonymization suite and privacy proxy that looks and works in every respect like a modern Chatbot & AI Agents, verified by rigorous automated tests.

  • New in 0.91 — AI configuration assistant: next to every AI, in the model picker and among the detected AIs in the Settings, a button installs or sets up what is missing: Google Antigravity CLI (agy) is used in the Chatbot & AI Agents with the Antigravity Desktop account, without tools and with the text already protected; Qwen 4 Max (Token Plan) and GLM 5.3 (Z.ai) are new services via API and Retrieve configuration links the keys already set in other tools without copying them; Ollama, LM Studio and Jan show the models already downloaded even when the service is stopped, with Install, Start and Download a recommended model. Downloads start only at your request, over HTTPS and with a verified digest or signature (chapter 2).
  • Since 0.90 — faster and parallel, with the same protection: the Privacy Filter and the Italian NER work together, each model has its own lock, interactive requests take a fast lane ahead of the queued documents, System 2 no longer asks redundant questions (a 12-page PDF goes from 234.6 to 132.0 seconds), the Vault is an SQLite database (with 100,000 entries a new item is saved in about 2 ms instead of 300), long audio is transcribed in batches and the Proxy also anonymizes the tool arguments of AI agents with a final no-exit check (chapters 9 and 11).
  • Chatbot & AI Agents (new interface, default tab): you talk to the chosen AI as in a modern assistant — conversations on the left, streamed answers with Markdown, highlighted code and Copy code, attachments with the paperclip or by dragging them, Enter to send and Shift+Enter for a new line — and the model is chosen at the bottom right: only the detected AIs can be selected (CLIs such as Claude Code and Antigravity CLI, local models of Ollama, LM Studio and Jan, services via API with a key), the others stay greyed out with the reason and, when possible, with the configuration assistant button. Every request goes through the Germano engine: the AI only receives the tags (e.g. [PERSONA_1]) and the answer comes back with the real data (chapter 2).
  • Glass Window (Transparent Inspection): a button at the top opens a frosted-glass panel that shows in real time everything sent to the model — original text, data intercepted by the privacy filter and the Vault, text actually sent, raw HTTP or CLI payload, raw answer stream — with Stop operation to halt everything at any moment and, on request, a review before every send (Send now / Block sending) (chapter 2).
  • Manual Sanitization & Vault: the tab next to the Chatbot & AI Agents area keeps all the batch work of the previous version — you drag files or whole folders onto the input box, the four boxes input, output, processed and failed show the files in real time like a file manager, failed documents are re-queued with one click — plus the manual sanitization of a text and the mapping archive (Vault) (chapter 2).
  • Remote Control, Germano Client and user management: in Server mode any device on the network opens from the browser, with nothing to install, the same interface — Chatbot & AI Agents with the Glass Window, manual sanitization of files and texts, settings — with the server's AIs filtered by Germano (shared CLIs, services via API such as Meta Muse, Kimi, DeepSeek, Qwen, GLM, Mistral, Grok, Perplexity and Gemini, the server's local models); Germano Client offers the same panel on the network PCs. Open access or user name and password; per-device processing options, locked and greyed out with the PA profile (chapters 2 and 11).
  • Endpoints for AI agents: Settings › Proxy & APIs shows the Proxy addresses (OpenAI format and Anthropic format) and, for each tool (Claude Code, Codex CLI, Cursor, Antigravity, Windsurf, OpenCode, Continue, Aider, OpenAI and Anthropic SDKs), where to set them, with instructions to copy; examples of the local REST APIs follow (chapter 12).
  • Silent updates, like Google Chrome: on by default. Only when the system reports that the PC is connected to the Internet, Germano checks download.germano.ai, downloads the new version in the background at low priority, prepares it next to the one in use and applies it at the next start in a few seconds, with no windows or notices interrupting your work. At most a discreet «Restart to update» appears at the top. Documents, Vault and settings are not touched and, if anything goes wrong, the current version stays. Status and options in Settings › Updates (chapter 13).
  • Office documents intact: Word, Excel, PowerPoint and OpenDocument files are edited directly in their XML. Bold, fonts, images, tables, formulas and macros stay identical. Footnotes, text boxes, comments and their authors, revisions, speaker notes, charts, metadata and preview thumbnails are anonymized too.
  • Safer PDFs: OCR also on scans with a digital stamp (registry protocol), pixels under the text of "searchable" scans are blacked out, rotated pages are handled correctly; form fields, comments, bookmarks, metadata and embedded attachments are anonymized; PAdES digital signatures (with the signer's name and tax code) are removed.
  • Fixed API Proxy: streaming for Claude Code and Codex (Anthropic and OpenAI Responses formats) is fully supported, also with attached images and PDFs; tool arguments remain valid JSON and batch analysis with caching makes long conversations much faster; since 0.90 tool argument values are anonymized at every level and a final check blocks the request if a detected item stays in clear.
  • Audio Files & Offline Speech Transcription (since 0.80, batched since 0.90): native support for voice recordings and audio files (.mp3, .wav, .m4a, .ogg, .flac, .opus, .aac, .wma, .amr, .aiff). Speech is transcribed 100% offline on your machine via the integrated Whisper Small INT8 model, ID3/Vorbis/MP4 metadata tags are sanitized, and the redacted transcript <name>.trascrizione.txt with [hh:mm:ss] timestamps is saved to output (also supported as direct attachments in Chatbot & AI Agents).
  • Multi-Format Compressed Archives (since 0.80): safe recursive extraction and redaction for .zip, .tar, .tar.gz, .tgz, .gz, .bz2, .xz, .7z and .rar archives (with bundled 7-Zip engine), hardened against Path Traversal and Decompression Bombs (up to 4 GB), automatically repacking sanitized files with their original folder hierarchy.
  • Extended Document Support: native RTF without Word, signed .p7m files (e.g. fattura.xml.p7m), JSON, TSV, Markdown, logs, source code, GIF and Office templates; .doc/.xls files that are actually renamed RTF, DOCX or HTML are recognized without Office.
  • More accurate recognition: the Italian model now analyzes long documents in full (it used to stop after a few lines); validated RegEx for European IBANs, tax codes (including omocodes or codes misread by OCR), payment cards, phone numbers, license plates and electronic ID cards; a name found in one place is redacted throughout the document.
  • Reliability: the engine shuts down by itself with the Germano window, files are processed only once fully copied, the Vault (an SQLite database in WAL mode since 0.90) is protected from concurrent writes, long documents get up to 60 minutes (configurable) and the Dashboard shows the progress and the reason for every error.
  • Security: the local API rejects requests coming from external websites and the internal engine is protected by a token. No document data is sent over the network: the only automatic connections are the update check, when Windows reports that the PC is connected to the Internet, and, if you installed Antigravity CLI, the check of your Google account's models (with no texts); the configuration assistant's downloads start only at your request.
  • For administrators: settings lock for the PA profile ("lock_settings": true), choice of the model precision (FP32/BF16), file name anonymization, separately configurable Anthropic service.

Supported systems: Windows 10/11, Windows Server and virtual machines

  • Windows 10 and 11, 64-bit.
  • Windows Server 2019, 2022 and 2025 (Standard and Datacenter), with the Desktop Experience for Germano's window. Windows Server 2019 does not include Microsoft Edge: without Edge (or Chrome) Germano does not use Internet Explorer, which cannot show the Dashboard, but stays active as a server without a window and shows the addresses to open (also from another computer); after installing Microsoft Edge its window is back. On Server Core, which has neither Edge nor the desktop, use the windowless mode (chapter 11).
  • Virtual machines: VMware (ESXi, Workstation), Hyper-V, Proxmox VE (KVM/QEMU), VirtualBox and cloud instances (AWS EC2, Azure, Google Compute Engine). No GPU is needed: the whole pipeline runs on the CPU; the number of threads adapts to the vCPUs and the precision to the processor (chapter 9). For network access the VM needs an adapter in bridged mode (or an external virtual switch): behind NAT you need TCP port 8181 forwarding and the address entered by hand in the clients, because auto-discovery (UDP 8182) does not cross NAT.
  • No external installation: the program contains Python 3.11 and the Microsoft Visual C++ 2015-2022 DLLs (vcruntime140.dll, vcruntime140_1.dll, msvcp140.dll, msvcp140_1.dll, msvcp140_2.dll, vcomp140.dll for OpenMP, concrt140.dll and the others): it also works on a freshly installed Windows Server, with no redistributables. The other DLLs used are standard Windows components.
  • The data (Vault, working folders, state) can live on virtual disks (vmdk, vhdx, qcow2) as on physical ones. A data folder on a network share (SMB or NFS) is protected by an operating-system lock: a second Germano, even from another computer, cannot use it together with the first one (the Vault cannot have two writers).

Glass Window: tutto ciò che arriva al modello, in tempo reale

Il pulsante Glass Window apre a destra un pannello in vetro smerigliato. In cima: lo stato della richiesta con il cronometro, il selettore delle richieste della sessione (per riesaminare quelle precedenti) e il pulsante rosso Interrompi operazione. Sotto, le cinque fasi illuminate man mano che avvengono e le cinque sezioni:

  1. Testo originale inserito — il messaggio, le istruzioni, il testo degli allegati e i turni precedenti, esattamente come li hai scritti.
  2. Filtro di privacy Germano e corrispondenze del Vault — le categorie trovate, il testo con i dati evidenziati e la tabella Originale → Etichetta → Affidabilità, con il tempo di analisi e quanto veniva dalla cache. Le etichette sono stabili: lo stesso dato ha sempre la stessa etichetta.
  3. Testo effettivo inviato al modello AI — i messaggi esatti che partono, istruzioni comprese: qui non deve comparire nessun dato personale.
  4. Payload HTTP / CLI grezzo — indirizzo, intestazioni (con le chiavi sempre oscurate) e corpo JSON della richiesta; per Claude Code il comando (senza testo tra gli argomenti), le variabili impostate da Germano, lo standard input e il payload HTTP catturato dal Proxy; per Antigravity CLI il comando, il profilo isolato, la riga dello standard input con le sole etichette e l'avviso che la richiesta va direttamente a Google.
  5. Stream in tempo reale della risposta (prima del ripristino) — i frammenti come arrivano dal modello, con le etichette, i contatori e, se attivati nelle Impostazioni, i frame SSE grezzi.

Interrompi operazione ferma tutto in qualsiasi momento: Germano chiude la connessione verso il servizio di AI (o termina la CLI con tutti i suoi processi) e scrive «Operazione interrotta dall'utente tramite Glass Window: nessun dato ulteriore è stato trasmesso o ricevuto.» Se l'interruzione avviene prima dell'invio, al modello non è arrivato nulla. Anche il pulsante di invio, durante una richiesta, diventa Interrompi operazione.

  • Revisione prima dell'invio (casella nel riquadro di scrittura): Germano si ferma dopo la protezione e mostra il payload esatto; parte solo con Invia ora, oppure Blocca invio e nulla esce.
  • Anteprima mentre scrivi: con la Glass Window aperta, le prime tre sezioni mostrano già cosa verrà oscurato, prima di inviare (l'analisi avviene sul motore di Germano: nessun dato esce).
  • Nulla di ciò che vedi nella Glass Window viene salvato o inviato altrove: resta nella finestra finché la chiudi.

Soglia di Confidenza IA (Cursore di Sicurezza)

Il cursore di sensibilità consente di impostare la soglia minima di certezza dell'Intelligenza Artificiale:

  • 0% (Massima Sicurezza - Profilo PA / GDPR Predefinito): Qualsiasi elemento che presenti anche il minimo dubbio viene oscurato. È la modalità consigliata per la Pubblica Amministrazione e per evitare sanzioni GDPR.
  • Valori intermedi (10% - 50%): Modalità bilanciata adatta a testi commerciali e di marketing per ridurre al minimo i falsi positivi.

Accelerazione Hardware

Germano include 3 modalità di esecuzione selezionabili:

  1. Automatico (Consigliato): usa una scheda NVIDIA (CUDA) se disponibile, altrimenti il processore. Nota: il pacchetto standard include PyTorch per CPU, che funziona su qualsiasi PC senza driver aggiuntivi; l'accelerazione GPU richiede di sostituire PyTorch con una versione CUDA.
  2. Solo CPU: esegue tutti i modelli sul processore centrale (funziona su qualsiasi PC, server o macchina virtuale, senza GPU né driver).
  3. Forza GPU NVIDIA: per installazioni con PyTorch CUDA; in caso di errore della GPU Germano passa comunque alla CPU.

Memoria RAM e Precisione del Modello

Il modello principale (1,5 miliardi di parametri) può essere caricato in due modi:

  • FP32 (veloce): circa 5,3 GB di RAM. Scelto automaticamente con almeno 12 GB di RAM, e anche con meno se ci sono almeno 7 GB liberi e il processore non ha il BF16 nativo.
  • BF16 (leggero): circa 2,7 GB di RAM. Scelto automaticamente quando la memoria non basta per FP32. Sui processori senza BF16 nativo (AVX2: Intel Haswell e Broadwell, Xeon E5 v3/v4, molti host di virtualizzazione) è da 4 a 10 volte più lento (misurato su un i5-4570: 12,4 s contro 1,6 s per blocco di testo); sui processori con AVX-512 o AMX (Xeon Scalable, AMD EPYC Zen 4) la differenza è contenuta.

Se il BF16 non funziona sul processore (operazioni mancanti), Germano passa da solo a FP32, sia all'avvio sia durante l'elaborazione, e lo annota nel registro. Requisiti consigliati: 16 GB di RAM (minimo 8 GB), almeno 4 processori (o vCPU) e 6 GB di spazio libero su disco. La scelta si può forzare in Impostazioni › Sistema e registro › Precisione del modello principale e vale dal successivo avvio del motore.

Processori, thread e macchine virtuali

Germano usa i processori che il sistema concede al programma (le vCPU di una macchina virtuale, o l'affinità impostata dall'amministratore): tutti fino a 2, poi uno lasciato libero per il server web, il sistema e gli altri servizi della macchina (su 4 core costa circa il 2% di velocità), al massimo 16. Il numero si cambia con "cpu_threads" in config.json (0 = automatico) o con la variabile GERMANO_CPU_THREADS; un OMP_NUM_THREADS già impostato dall'amministratore viene rispettato. Il registro del motore (daemon.log) e il suggerimento sullo stato del motore mostrano processori, thread, precisione, presenza del BF16 nativo e l'eventuale macchina virtuale (VMware, Hyper-V, KVM/Proxmox, VirtualBox, cloud). Non serve nessuna GPU: tutta la pipeline (modelli di testo, OCR, volti, firme, targhe) gira su CPU.

Prestazioni e lavoro in parallelo (novità 0.90)

Dalla 0.90 il motore lavora in parallelo dove prima aspettava, senza cambiare ciò che viene protetto: sugli stessi file i dati oscurati coincidono con quelli della 0.80.

  • Privacy Filter e Italian NER insieme: i due modelli del testo analizzano lo stesso lotto nello stesso momento (il NER gira in ONNX Runtime in un thread a parte).
  • Un lock per modello: Privacy Filter, Italian NER, OCR, volti, firme e targhe hanno ciascuno il proprio lock, così richieste diverse usano modelli diversi nello stesso momento (per esempio l'OCR di una scansione in coda e il testo di una richiesta del Proxy). All'avvio Italian NER e OCR si caricano mentre si carica il Privacy Filter.
  • Corsia preferenziale (Fast-Lane): le richieste interattive (Chatbot e Agenti AI, Proxy, API REST, Remote Control e client della rete) passano davanti ai documenti della cartella input su Privacy Filter, OCR e Sistema 2: aspettano al massimo il lotto in corso.
  • Documenti a lotti: i PDF scansionati vengono elaborati a finestre di 8 pagine e le immagini dei documenti Office a lotti; il testo letto dall'OCR si analizza in un'unica chiamata, con la propagazione dei dati fra le pagine.
  • Sistema 2 senza domande superflue: i casi dubbi su parole già oscurate in un altro punto del documento non vengono chiesti al modello locale (la propagazione li oscurerebbe comunque; sul corpus di prova erano il 70% delle domande). Un dubbio non chiesto resta sempre oscurato.
  • Audio a lotti: dalle registrazioni di 60 secondi in su Whisper trascrive i segmenti di parlato a lotti di 8, con ripiego automatico sul modo in serie.
  • File per percorso e cache: fra server e motore i file passano per percorso (niente base64 dentro JSON); la cronologia e gli allegati già protetti arrivano dalla cache (fino a 256 MB, svuotata insieme al Vault).

La tabella delle corrispondenze risiede localmente in extracted/deanonymize_vault.db (SQLite in modalità WAL, dalla 0.90: si scrivono e si leggono solo le voci nuove), con una copia portabile nel formato di sempre in extracted/deanonymize_vault.json (aggiornata a ogni salvataggio fino a 5.000 voci, poi ogni 5 minuti e alla chiusura del motore; su un disco di rete resta il solo JSON): se sostituisci a mano il JSON (per esempio copiandolo da un'altra installazione), Germano ne importa le corrispondenze senza perdere quelle già presenti. Nella scheda Sanitizzazione Manuale & Vault, riquadro Archivio delle corrispondenze (Vault): Mostra visualizza tutte le etichette attive, Svuota azzera le corrispondenze per iniziare una nuova sessione pulita (i documenti protetti in precedenza non potranno più essere ripristinati).

Il Vault contiene i dati veri in chiaro: conserva la cartella Documenti\Germano AI su un disco protetto (es. BitLocker) e con accesso riservato. Se disattivi l'interruttore Ripristino automatico dei dati originali, Germano usa etichette non numerate (es. [PERSONA]) e non salva più i dati nel Vault: l'anonimizzazione diventa irreversibile.

AI Confidence Threshold (Safety Slider)

The sensitivity slider defines the minimum statistical probability threshold required for AI redactions:

  • 0% (Maximum Safety - Default GDPR / Public Administration Profile): Redacts any span that raises even the slightest suspicion. Recommended for strict compliance scenarios.
  • Balanced Values (10% - 50%): Optimal for commercial and marketing copy to eliminate occasional false positives.

Hardware Acceleration Modes

Germano supports 3 selectable compute execution backends:

  1. Automatic (Recommended): uses an NVIDIA (CUDA) GPU when available, otherwise the CPU. Note: the standard package ships the CPU build of PyTorch, which works on any PC without extra drivers; GPU acceleration requires replacing PyTorch with a CUDA build.
  2. CPU Only: executes models exclusively on the CPU (works on any PC, server or virtual machine, with no GPU or drivers).
  3. Force NVIDIA GPU: for installations with CUDA PyTorch; on GPU errors Germano still falls back to the CPU.

RAM and Model Precision

The main model (1.5 billion parameters) can be loaded in two ways:

  • FP32 (fast): about 5.3 GB of RAM. Selected automatically with at least 12 GB of RAM, and also with less when at least 7 GB are free and the CPU has no native BF16.
  • BF16 (light): about 2.7 GB of RAM. Selected automatically when memory is not enough for FP32. On CPUs without native BF16 (AVX2: Intel Haswell and Broadwell, Xeon E5 v3/v4, many virtualization hosts) it is 4 to 10 times slower (measured on an i5-4570: 12.4 s versus 1.6 s per text block); on CPUs with AVX-512 or AMX (Xeon Scalable, AMD EPYC Zen 4) the difference is small.

If BF16 does not work on the CPU (missing operations), Germano switches to FP32 by itself, both at startup and during processing, and records it in the log. Recommended: 16 GB of RAM (8 GB minimum), at least 4 processors (or vCPUs) and 6 GB of free disk space. The choice can be forced in Settings › System & log › Precision of the main model and applies from the next engine start.

Processors, threads and virtual machines

Germano uses the processors the system grants to the program (the vCPUs of a virtual machine, or the affinity set by the administrator): all of them up to 2, then one is left free for the web server, the system and the other services of the machine (on 4 cores it costs about 2% of speed), at most 16. The number is changed with "cpu_threads" in config.json (0 = automatic) or with the GERMANO_CPU_THREADS variable; an OMP_NUM_THREADS already set by the administrator is honored. The engine log (daemon.log) and the engine status tooltip show processors, threads, precision, native BF16 and the virtual machine, if any (VMware, Hyper-V, KVM/Proxmox, VirtualBox, cloud). No GPU is needed: the whole pipeline (text models, OCR, faces, signatures, plates) runs on the CPU.

Performance and parallel work (new in 0.90)

Since 0.90 the engine works in parallel where it used to wait, without changing what is protected: on the same files the masked data match those of 0.80.

  • Privacy Filter and Italian NER together: the two text models analyze the same batch at the same time (the NER runs in ONNX Runtime on a separate thread).
  • One lock per model: Privacy Filter, Italian NER, OCR, faces, signatures and plates each have their own lock, so different requests use different models at the same time (for example the OCR of a queued scan and the text of a Proxy request). At start the Italian NER and OCR load while the Privacy Filter loads.
  • Fast lane: interactive requests (Chatbot & AI Agents, Proxy, REST API, Remote Control and network clients) go ahead of the input folder documents on the Privacy Filter, OCR and System 2: they wait at most for the batch in progress.
  • Documents in batches: scanned PDFs are processed in windows of 8 pages and Office document images in batches; the OCR text is analyzed in a single call, with data propagation across pages.
  • System 2 without redundant questions: doubtful cases about words already masked elsewhere in the document are not asked to the local model (propagation would mask them anyway; on the test corpus they were 70% of the questions). A question that is not asked always stays masked.
  • Batched audio: from recordings of 60 seconds up, Whisper transcribes the speech segments in batches of 8, with automatic fallback to the sequential mode.
  • Files by path and caches: between server and engine files travel by path (no base64 inside JSON); history and attachments already protected come from the cache (up to 256 MB, emptied together with the Vault).

The reverse de-anonymization dictionary is persisted locally in extracted/deanonymize_vault.db (SQLite in WAL mode, since 0.90: only new entries are written and read), with a portable copy in the usual format in extracted/deanonymize_vault.json (updated at every save up to 5,000 entries, then every 5 minutes and when the engine closes; on a network drive only the JSON is kept): if you replace the JSON by hand (for example copying it from another installation), Germano imports its mappings without losing the existing ones. 11. Transparent AI Agent Proxy, Germano Client & User Management

Germano AI integra un Proxy API Bidirezionale Intelligente conforme allo standard OpenAI (`/v1/chat/completions`), Anthropic (`/v1/messages`) e OpenAI Responses (`/v1/responses`).

Come Funziona il Proxy:

Gli strumenti e gli agenti IA che permettono di cambiare l'indirizzo del servizio (come Claude Code, OpenAI Codex CLI, Aider, Qwen Code, OpenCode, Continue) indirizzano le loro chiamate API verso http://127.0.0.1:8181/v1 invece che direttamente verso il cloud. Germano intercetta la chiamata in uscita, anonimizza al volo prompt, messaggi, immagini e argomenti delle funzioni (`tool_calls`), inoltra la richiesta al provider prescelto e, quando la risposta torna indietro, rimette automaticamente i dati veri al loro posto prima di restituirla allo strumento. Cursor, Windsurf, Claude Desktop e Antigravity non si possono instradare nel Proxy (capitolo 12).

Supporto Streaming SSE con `StreamTagBuffer`

Nelle risposte in streaming (Server-Sent Events), i token arrivano spezzati frammento per frammento. Se un modello cloud restituisce un tag suddiviso in più token (es. [PER + SONA_1]), il buffer intelligente StreamTagBuffer di Germano trattiene temporaneamente i caratteri finché il tag non è completo, lo de-anonimizza al volo e rilascia immediatamente il testo originale senza ritardi evidenti.

Supporto Chiamate Funzione & Scrittura File (`tool_calls`)

Quando Claude Code o Codex invocano strumenti come write_file o edit_file, Germano de-anonimizza ricorsivamente la stringa JSON contenuta in function.arguments (e in input_json_delta per Claude), con l'escape JSON corretto: il file che l'agente scrive sul disco conterrà sempre i dati reali corretti senza alcuna etichetta residua.

Cosa viene anonimizzato e cosa viene bloccato

  • Anonimizzati: messaggi, istruzioni di sistema, argomenti e risultati dei tool, riassunti del ragionamento, immagini (image_url, input_image, blocchi image di Claude) e documenti allegati (PDF, Word, Excel, testo) nei formati OpenAI, Responses e Anthropic.
  • Argomenti degli strumenti (dalla 0.90): i valori dentro tool_use.input, function.arguments e functionCall.args (Gemini) vengono anonimizzati a ogni livello, anche sotto chiavi come name, id, status o type; la busta del protocollo (identificativi e nomi degli strumenti) resta intatta. Anonimizzati anche il testo citato delle citazioni, metadata, user e il nome dei partecipanti; le risposte non in streaming ripristinano gli argomenti.
  • Lasciati intatti: i blocchi thinking firmati di Claude (sono generati dall'AI a partire dal testo già anonimo e una modifica invaliderebbe la firma), definizioni dei tool e parametri tecnici.
  • Bloccati (fail-safe): audio (la voce è un dato biometrico) e allegati di formato sconosciuto; se il motore IA non è attivo la richiesta non viene inoltrata.
  • Controllo finale di non-uscita (dalla 0.90): prima dell'inoltro Germano ricontrolla l'intera richiesta: se un dato appena rilevato è rimasto in un campo che non può anonimizzare, la richiesta viene bloccata con l'errore 422 e non parte nulla.
  • Sono inoltrati gli header necessari (Authorization, x-api-key, anthropic-version, anthropic-beta...) e i parametri dell'indirizzo (es. ?beta=true); è supportato anche /v1/messages/count_tokens.
  • Le connessioni verso il servizio IA usano il proxy di sistema e i certificati di Windows (utile nelle reti aziendali con ispezione TLS).
  • La mappa delle sostituzioni di ogni richiesta viene registrata in extracted/proxy_sessions/AAAA-MM-GG.jsonl (disattivabile con "save_proxy_logs": false in config.json).

Prestazioni: la prima richiesta di una conversazione lunga può richiedere alcune decine di secondi su CPU; i messaggi già analizzati vengono memorizzati, quindi le richieste successive analizzano solo il testo nuovo.

A prova di errore

Prima di inviare qualsiasi dato il Client verifica — senza inviare dati personali — che all'indirizzo risponda un vero Germano Server, che l'accesso sia consentito (libero, oppure sessione valida) e che il motore sia pronto; altrimenti non invia nulla e spiega il perché. Si collega sempre direttamente al server, mai attraverso un proxy di sistema o aziendale. Codici di uscita: 0 ok, 1 server non raggiungibile, 2 uso errato, 3 accesso richiesto o sessione non valida, 4 motore non pronto, 5 CLI non installata o non proteggibile, 6 opzioni bloccate dal profilo PA del server.

Gestione utenti

Di base l'accesso dalla rete è libero: chiunque sia collegato alla rete locale può usare il motore, il Proxy e il Remote Control. Per limitarlo, nella Dashboard del server apri Impostazioni › Modalità e rete › Accesso dalla rete › Gestione utenti, aggiungi uno o più utenti (nome con lettere, cifre e . _ @ -; password di almeno 8 caratteri) e attiva «Richiedi utente e password per l'accesso dalla rete». Da quel momento:

  • il browser mostra la schermata di accesso; la sessione resta in un cookie protetto (HttpOnly, SameSite=Strict) e dura 30 giorni dall'ultimo uso;
  • Germano Client accede con client login --user mario (la password si digita senza mostrarla) o dal suo pannello, e conserva solo la sessione, mai la password;
  • CLI e SDK collegati al Proxy usano il token creato in Impostazioni › Collega i tuoi strumenti del Remote Control;
  • le richieste senza accesso valido ricevono 401; dopo 5 tentativi errati in 10 minuti l'indirizzo viene bloccato per 10 minuti (429).

Le password sono salvate in config.json solo come impronta PBKDF2-SHA256 (600.000 iterazioni, sale casuale), le sessioni solo come impronta SHA-256. Cambiare una password chiude le sessioni di quell'utente; disattivare o riattivare la gestione utenti le chiude tutte; eliminando l'ultimo utente la gestione utenti si disattiva. Dal computer del server (127.0.0.1) si accede sempre senza credenziali e solo da lì si gestiscono utenti, modalità e impostazioni del server; con "lock_settings": true anche la gestione utenti è bloccata.

Sicurezza dell'accesso dalla rete

  • Ripristino limitato alla richiesta: per le richieste dalla rete e per le AI condivise il server rimette nella risposta solo i dati della stessa richiesta, mai altri dati del Vault; un'etichetta di un altro documento resta un'etichetta. Dal computer del server il Proxy continua a usare l'intero Vault, come prima.
  • Le AI condivise sono eseguite sul server senza strumenti: nessuna AI può leggere file o eseguire comandi sul server per conto dei client.
  • In rete locale il collegamento è HTTP, quindi non cifrato: usa il Remote Control su reti fidate (la rete dell'ufficio, non una Wi-Fi pubblica) e, se serve la cifratura, metti davanti al server un proxy HTTPS.
  • Il Vault del server (extracted/deanonymize_vault.db e la copia deanonymize_vault.json) non è cifrato: proteggi l'accesso al computer del server.

Rete e firewall su Windows Server e nelle macchine virtuali

  • L'installer crea la regola del firewall «Germano AI (Server LAN)» per il Python del programma, valida per TCP 8181 e UDP 8182 (anche se le porte cambiano) sulle reti private e di dominio, quindi anche sui server di un dominio Active Directory.
  • Se una scheda di rete è classificata come Pubblica (frequente nelle macchine virtuali e nei server in gruppo di lavoro), Windows blocca i client. La Dashboard del server lo segnala con il comando per correggerlo (PowerShell come amministratore): Set-NetConnectionProfile -InterfaceAlias "Ethernet" -NetworkCategory Private.
  • Se i criteri di gruppo ignorano le regole locali del firewall, la Dashboard lo segnala: l'amministratore di dominio deve consentire runtime\python.exe di Germano (TCP 8181, UDP 8182) con un criterio. Segnala anche una regola mancante, disattivata o per un altro programma, con il comando netsh per ricrearla.
  • Le schede di rete virtuali (VirtIO, vmxnet3, switch di Hyper-V, bridge di Proxmox) funzionano come quelle fisiche: la Dashboard e il Remote Control mostrano per primo l'indirizzo della scheda usata per uscire verso la rete ed escludono gli indirizzi automatici 169.254.x.x.

Germano AI includes an embedded Bidirectional Transparent Proxy compliant with the OpenAI standard (`/v1/chat/completions`), Anthropic standard (`/v1/messages`), and Responses API (`/v1/responses`).

How the Proxy Operates:

The AI tools and agents that let you change the service address (such as Claude Code, OpenAI Codex CLI, Aider, Qwen Code, OpenCode, Continue) point their API requests to http://127.0.0.1:8181/v1 rather than direct cloud endpoints. Germano intercepts outgoing traffic, redacts on the fly prompts, system instructions, images, and function arguments (`tool_calls`), forwards the clean request to OpenAI/Anthropic, and when the stream returns, transparently re-injects real data before handing the response back to the tool. Cursor, Windsurf, Claude Desktop and Antigravity cannot be routed through the Proxy (chapter 12).

SSE Streaming via `StreamTagBuffer`

In streaming completions (Server-Sent Events), tokens arrive fragmented across tiny chunks. If an LLM emits a tag split across chunks (e.g. [PER + SONA_1]), Germano's StreamTagBuffer buffers fragments until the bracket closes, queries the local vault, and emits the real restored word without perceptible latency.

Native Tool Calls & File Editing (`tool_calls`)

When autonomous agents like Claude Code or Codex invoke file creation or patching tools (`write_file`, `edit_file`), Germano recursively de-anonymizes the JSON string within function.arguments (and input_json_delta for Claude) with correct JSON escaping. As a result, code or documents written to disk by the AI will always feature the authentic real data with zero leftover placeholder tags.

What is anonymized and what is blocked

  • Anonymized: messages, system instructions, tool arguments and results, reasoning summaries, images (image_url, input_image, Claude image blocks) and attached documents (PDF, Word, Excel, text) in the OpenAI, Responses and Anthropic formats.
  • Tool arguments (since 0.90): the values inside tool_use.input, function.arguments and functionCall.args (Gemini) are anonymized at every level, also under keys such as name, id, status or type; the protocol envelope (tool identifiers and names) stays intact. The cited text of citations, metadata, user and participant names are anonymized too; non-streaming responses restore the arguments.
  • Left untouched: Claude's signed thinking blocks (generated by the AI from already anonymized text; any change would invalidate the signature), tool definitions and technical parameters.
  • Blocked (fail-safe): audio (voice is biometric data) and attachments of unknown type; if the AI engine is not running the request is never forwarded.
  • Final no-exit check (since 0.90): before forwarding, Germano checks the whole request again: if a just-detected item remained in a field that it cannot anonymize, the request is blocked with error 422 and nothing is sent.
  • Required headers are forwarded (Authorization, x-api-key, anthropic-version, anthropic-beta...) together with URL parameters (e.g. ?beta=true); /v1/messages/count_tokens is supported too.
  • Connections to the AI service use the system proxy and the Windows certificate store (useful on corporate networks with TLS inspection).
  • The replacement map of each request is logged to extracted/proxy_sessions/YYYY-MM-DD.jsonl (can be disabled with "save_proxy_logs": false in config.json).

Performance: the first request of a long conversation may take tens of seconds on CPU; already analyzed messages are cached, so following requests only analyze new text.

Fail-safe

Before sending any data the Client checks — without sending any personal data — that a real Germano Server answers at the address, that access is allowed (open, or a valid session) and that the engine is ready; otherwise it sends nothing and explains why. It always connects to the server directly, never through a system or corporate proxy. Exit codes: 0 ok, 1 server unreachable, 2 wrong usage, 3 sign-in required or invalid session, 4 engine not ready, 5 CLI not installed or not protectable, 6 options locked by the server's PA profile.

User management

By default network access is open: anyone connected to the local network can use the engine, the Proxy and the Remote Control. To restrict it, in the server's Dashboard open Settings › Mode & network › Network access › User management, add one or more users (name with letters, digits and . _ @ -; password of at least 8 characters) and enable «Require user name and password for network access». From then on:

  • the browser shows the sign-in screen; the session stays in a protected cookie (HttpOnly, SameSite=Strict) and lasts 30 days from the last use;
  • Germano Client signs in with client login --user mario (the password is typed without being shown) or from its panel, and keeps only the session, never the password;
  • CLIs and SDKs connected to the Proxy use the token created in the Remote Control's Settings › Connect your tools;
  • requests without valid access get 401; after 5 wrong attempts in 10 minutes the address is blocked for 10 minutes (429).

Passwords are stored in config.json only as a PBKDF2-SHA256 hash (600,000 iterations, random salt), sessions only as a SHA-256 hash. Changing a password closes that user's sessions; turning user management off or on closes them all; deleting the last user turns user management off. From the server computer (127.0.0.1) access never needs credentials and only from there are users, mode and server settings managed; with "lock_settings": true user management is locked too.

Network access security

  • Restoration limited to the request: for network requests and for the shared AIs the server puts back into the answer only the data of the same request, never other Vault data; a tag of another document stays a tag. From the server computer the Proxy keeps using the whole Vault, as before.
  • The shared AIs run on the server without tools: no AI can read files or run commands on the server on behalf of the clients.
  • On the local network the connection is HTTP, therefore not encrypted: use the Remote Control on trusted networks (the office network, not a public Wi-Fi) and, if encryption is needed, put an HTTPS proxy in front of the server.
  • The server's Vault (extracted/deanonymize_vault.db and the copy deanonymize_vault.json) is not encrypted: protect access to the server computer.

Network and firewall on Windows Server and in virtual machines

  • The installer creates the «Germano AI (Server LAN)» firewall rule for the program's Python, valid for TCP 8181 and UDP 8182 (even if the ports change) on private and domain networks, therefore also on servers of an Active Directory domain.
  • If a network adapter is classified as Public (common in virtual machines and in workgroup servers), Windows blocks the clients. The server's Dashboard reports it with the command to fix it (PowerShell as administrator): Set-NetConnectionProfile -InterfaceAlias "Ethernet" -NetworkCategory Private.
  • If Group Policy ignores local firewall rules, the Dashboard reports it: the domain administrator must allow Germano's runtime\python.exe (TCP 8181, UDP 8182) with a policy. It also reports a rule that is missing, disabled or for another program, with the netsh command to recreate it.
  • Virtual network adapters (VirtIO, vmxnet3, Hyper-V switch, Proxmox bridge) work like physical ones: the Dashboard and the Remote Control show first the address of the adapter used to reach the network and leave out the automatic 169.254.x.x addresses.

13. FAQ & Troubleshooting

D: Germano AI invia qualcosa su Internet?

R: Nessun dato dei documenti. L'anonimizzazione di documenti e testi avviene interamente sul PC: gli 8 modelli IA risiedono nella cartella models/ e la telemetria delle librerie è disattivata. Le sole connessioni sono l'aggiornamento silenzioso, solo se il sistema segnala che il PC è connesso a Internet (guarda nella cartella ufficiale di download download.germano.ai se c'è una versione più recente e la scarica: vedi la domanda sugli aggiornamenti), le richieste che fai tu all'AI scelta, con Chatbot e Agenti AI o il Proxy API, che partono solo già anonimizzate, e i download che chiedi tu all'Assistente di configurazione (dagli indirizzi ufficiali, con impronta o firma verificate). Se hai installato Antigravity CLI, mentre la Dashboard è aperta Germano le chiede circa ogni 10 minuti l'elenco dei modelli del tuo account (agy models: la CLI contatta Google, senza testi né documenti) e, quando la usi, le sue istruzioni interne vanno a Google direttamente, come dichiara la Glass Window.

D: Quanta memoria serve?

R: Consigliati 16 GB di RAM (minimo 8 GB). Con meno di 12 GB Germano usa comunque la versione veloce (FP32) se ci sono almeno 7 GB liberi; altrimenti carica il modello principale in versione leggera (BF16): funziona, ma sui processori senza BF16 nativo l'analisi del testo è da 4 a 10 volte più lenta. In una macchina virtuale assegna almeno 12 GB di RAM e 4 vCPU. Vedi il capitolo 9.

D: Germano funziona su Windows Server o in una macchina virtuale?

R: Sì. Windows Server 2019, 2022 e 2025 e le macchine virtuali VMware, Hyper-V, Proxmox VE, VirtualBox e cloud sono supportati, senza GPU e senza installare altro (le DLL di Visual C++ sono incluse). Su Windows Server 2019, che non ha Microsoft Edge, Germano resta attivo come server senza finestra e indica gli indirizzi da aprire; per avviarlo senza finestra fin dall'inizio, anche all'accensione del server: Germano.exe --no-browser --mode=server (capitolo 11).

D: Dagli altri computer il Remote Control non si apre

R: Controlla le Impostazioni del server (Modalità e rete › Accesso dalla rete): se la scheda di rete è classificata come Pubblica, se la regola del firewall manca o se i criteri di gruppo ignorano le regole locali, la Dashboard lo dice con il comando per correggerlo. In una macchina virtuale con rete NAT serve l'inoltro della porta TCP 8181 (oppure una scheda in modalità bridge) e l'indirizzo va indicato a mano nei client.

D: Il motore non parte o compare un messaggio rosso di errore

R: Il messaggio in alto nella Dashboard indica la causa; il dettaglio completo è nel file daemon.log nella cartella Documenti\Germano AI. Su alcuni PC appena installati la funzione di Windows Smart App Control o l'antivirus possono bloccare i componenti IA: Germano lo segnala tempestivamente all'avvio.

D: Cosa succede se il programma indica che la porta 8181 è occupata?

R: Se Germano è già aperto, un nuovo avvio di Germano si apre semplicemente la Dashboard esistente. Se la porta è usata da un altro programma, chiudilo oppure imposta un'altra porta in config.json (es. "port": 8010) e aggiorna di conseguenza l'indirizzo del Proxy negli editor.

D: Perché vedo l'avviso «Sono rimasti aperti ... processi del motore»?

R: Il motore IA si chiude da solo quando chiudi la finestra di Germano; l'avviso può comparire solo dopo un arresto anomalo del PC. Basta cliccare Chiudi processi secondari nell'avviso in cima alla pagina.

D: Perché un file .doc o .ppt finisce tra i «Non riusciti»?

R: I vecchi formati binari di Office si possono convertire solo con Microsoft Office o LibreOffice installati. Su un PC senza Office salva il documento come .docx/.pptx, oppure installa LibreOffice: Germano lo usa automaticamente. Il motivo esatto di ogni errore è indicato nella scheda Non riusciti; risolto il problema, usa Rimetti in coda.

D: Come funzionano gli aggiornamenti? Devo fare qualcosa?

R: No: come Google Chrome, Germano si aggiorna da solo in silenzio (attivo di default). Circa 20 secondi dopo l'avvio (30 per Germano Client) e poi ogni 6 ore, solo se il sistema segnala che il PC è connesso a Internet, Germano legge https://download.germano.ai/version.json (l'unica fonte degli aggiornamenti). Se c'è una versione più recente:

  1. scarica il nuovo installer in background, a bassa priorità (non rallenta il lavoro), e ne controlla dimensione e struttura;
  2. su Windows lo prepara subito, in silenzio e sempre a bassa priorità, in una cartella accanto a quella del programma (Germano AI.nuovo), senza toccare la versione in uso;
  3. al successivo avvio la nuova versione prende il posto della vecchia in pochi secondi e Germano si apre già aggiornato. Nessuna finestra, nessun banner, nessuna domanda.

Quando l'aggiornamento è pronto compare solo un discreto «Riavvia per aggiornare» in alto (e un puntino sulla scheda Impostazioni): chi vuole lo applica subito, altrimenti si applica da solo al prossimo avvio. In Impostazioni › Aggiornamenti, come nella pagina Informazioni di Chrome, si vede lo stato: «Germano AI è aggiornato (v0.91)» con l'ora dell'ultimo controllo, «Download dell'aggiornamento in background…» con la barra di avanzamento, «Riavvia Germano per applicare l'aggiornamento». Su macOS e Linux il pacchetto si scarica allo stesso modo e si apre con il programma di installazione del sistema quando lo decidi tu (servono le tue conferme). Germano Client si aggiorna nello stesso modo.

Cartelle di lavoro, Vault e config.json nella cartella Documenti/Germano AI non vengono mai toccati. Se un aggiornamento non va a buon fine resta la versione in uso e non viene riprovato a ogni avvio. Su un PC isolato o offline non avviene alcun tentativo di connessione. Le opzioni: Aggiorna Germano automaticamente in background ("auto_update" in config.json; se spenta, Germano si limita a segnalare la nuova versione) e Controlla le nuove versioni quando il sistema segnala una connessione a Internet ("check_updates"). Controlla ora esegue subito un controllo.

D: Cosa mostra esattamente la Glass Window? Posso fermare una richiesta già partita?

R: La Glass Window mostra in tempo reale le cinque fasi di ogni richiesta dell'area Chatbot e Agenti AI: il testo originale, i dati trovati dal filtro di privacy con le etichette del Vault, il testo effettivamente inviato al modello, il payload HTTP o CLI esatto (con le chiavi oscurate) e lo stream grezzo della risposta. Interrompi operazione ferma la richiesta in qualsiasi momento: la connessione verso il servizio di AI viene chiusa (o la CLI viene terminata con tutti i suoi processi) e da quel momento nessun dato viene trasmesso o ricevuto. Per non far partire nulla senza il tuo consenso attiva Revisione prima dell'invio: la richiesta parte solo con Invia ora. Il contenuto della Glass Window non viene salvato da nessuna parte.

D: Antigravity, Qwen 4 Max, GLM 5.3 o Ollama sono in grigio: come li rendo utilizzabili?

R: Usa il pulsante accanto alla voce (nel selettore in basso a destra o in Impostazioni › AI, chiavi e Chatbot). Per Antigravity, Installa CLI installa Antigravity CLI, che usa l'account già collegato in Antigravity Desktop (se manca, Accedi con Google). Qwen e GLM vogliono una chiave del piano giusto (Qwen4-Max solo con il Token Plan; chiavi diverse per piano e regione): Recupera configurazione collega quella già impostata in un altro strumento senza copiarla, altrimenti inseriscila con «Chiave». Per Ollama, LM Studio e Jan spenti, Avvia; se non sono installati, Installa (Ollama su Windows) o la pagina ufficiale; senza modelli, Scarica modello consigliato. Il Remote Control e Germano Client non hanno l'assistente: si usa sul computer del server.

D: Come impedisco agli operatori di disattivare i filtri (Profilo PA)?

R: L'amministratore imposta in config.json i valori "compliance_mode": "PA" e "lock_settings": true: da quel momento la Dashboard mostra il lucchetto accanto al profilo e rifiuta ogni modifica dei filtri; il Remote Control e Germano Client mostrano le opzioni in grigio e il server rifiuta le modifiche (403).

D: I file protetti mantengono la grafica e i font originali?

R: Sì. Word, Excel, PowerPoint e OpenDocument vengono modificati direttamente nel loro XML: formattazione, immagini, tabelle, formule e macro restano intatte e cambia solo il testo personale (l'etichetta prende lo stile della prima parte del dato sostituito). Nei PDF le etichette vengono inserite al posto del testo rimosso, con un corpo ridotto se lo spazio è stretto.

D: Come trasferisco documenti e dati protetti in una nuova cartella o su un altro PC?

R: Chiudi Germano (così la copia del Vault è aggiornata) e copia dalla cartella precedente il file extracted/deanonymize_vault.json (indispensabile per ripristinare i dati reali nei documenti protetti) e, facoltativamente, config.json con le tue preferenze. All'avvio Germano importa le corrispondenze del JSON nel proprio database (deanonymize_vault.db) senza perdere quelle già presenti.

Q: Does Germano AI transmit any data over the Internet?

A: No document data. Document and text anonymization runs entirely on the PC: all 8 AI models live in models/ and library telemetry is disabled. The only connections are the silent update, only when the system reports that the PC is connected to the Internet (it looks in the official download folder download.germano.ai for a newer version and downloads it: see the question about updates), the requests you make to the AI you chose, with the Chatbot & AI Agents or the API Proxy, which only leave already anonymized, and the downloads you ask the configuration assistant for (from the official addresses, with a verified digest or signature). If you installed Antigravity CLI, while the Dashboard is open Germano asks it about every 10 minutes for the list of your account's models (agy models: the CLI contacts Google, with no texts or documents) and, when you use it, its internal instructions go to Google directly, as the Glass Window states.

Q: How much memory is needed?

A: 16 GB of RAM recommended (8 GB minimum). With less than 12 GB Germano still uses the fast version (FP32) when at least 7 GB are free; otherwise it loads the main model in its light version (BF16): it works, but on CPUs without native BF16 text analysis is 4 to 10 times slower. In a virtual machine assign at least 12 GB of RAM and 4 vCPUs. See chapter 9.

Q: Does Germano work on Windows Server or in a virtual machine?

A: Yes. Windows Server 2019, 2022 and 2025 and VMware, Hyper-V, Proxmox VE, VirtualBox and cloud virtual machines are supported, with no GPU and nothing else to install (the Visual C++ DLLs are included). On Windows Server 2019, which has no Microsoft Edge, Germano stays active as a server without a window and shows the addresses to open; to start it without a window from the beginning, also when the server boots: Germano.exe --no-browser --mode=server (chapter 11).

Q: The Remote Control does not open from the other computers

A: Check the server Settings (Mode & network › Network access): if the network adapter is classified as Public, if the firewall rule is missing or if Group Policy ignores local rules, the Dashboard says so with the command to fix it. In a virtual machine with NAT networking you need TCP port 8181 forwarding (or a bridged adapter) and the address must be entered by hand in the clients.

Q: The engine does not start or a red error message appears

A: The message at the top of the Dashboard shows the cause; full details are in daemon.log in the Documents\Germano AI folder. On some freshly installed PCs, Windows Smart App Control or the antivirus may block the AI components: Germano promptly reports it at startup.

Q: What if port 8181 is reported in use?

A: If Germano is already open, launching Germano again simply opens the existing Dashboard. If another program uses the port, close it or set a different port in config.json (e.g. "port": 8010) and update the Proxy address in your editors.

Q: Why do I see the «Sono rimasti aperti ... processi del motore» (engine processes left open) notice?

A: The AI engine stops automatically when you close the Germano window; the notice can only appear after an abnormal shutdown of the PC. Simply click Chiudi processi secondari (Close orphaned processes) in the notice at the top of the page.

Q: Why does a .doc or .ppt file end up among the «Non riusciti» (failed)?

A: Legacy binary Office formats can only be converted with Microsoft Office or LibreOffice installed. On a PC without Office, save the document as .docx/.pptx, or install LibreOffice: Germano uses it automatically. The exact reason of each failure is shown in the Non riusciti tab; once the problem is solved, use Rimetti in coda (Queue again).

Q: How do updates work? Do I need to do anything?

A: No: like Google Chrome, Germano updates itself silently (on by default). About 20 seconds after startup (30 for Germano Client) and then every 6 hours, only when the system reports that the PC is connected to the Internet, Germano reads https://download.germano.ai/version.json (the only update source). If there is a newer version:

  1. it downloads the new installer in the background, at low priority (it does not slow down your work), and checks its size and structure;
  2. on Windows it prepares it right away, silently and still at low priority, in a folder next to the program's one (Germano AI.nuovo), without touching the version in use;
  3. at the next start the new version replaces the old one in a few seconds and Germano opens already updated. No windows, no banners, no questions.

When the update is ready only a discreet «Restart to update» appears at the top (and a dot on the Settings tab): whoever wants applies it right away, otherwise it is applied by itself at the next start. Settings › Updates, like Chrome's About page, shows the status: «Germano AI is up to date (v0.91)» with the time of the last check, «Downloading the update in the background…» with the progress bar, «Restart Germano to apply the update». On macOS and Linux the package is downloaded the same way and opened with the system installer when you decide (your confirmations are needed). Germano Client updates itself the same way.

Working folders, Vault and config.json in Documents/Germano AI are never touched. If an update fails, the version in use is kept and it is not retried at every start. On a disconnected or offline PC no connection attempt is made. The options: Update Germano automatically in the background ("auto_update" in config.json; when off, Germano only reports the new version) and Check for new versions when the system reports an Internet connection ("check_updates"). Check now runs a check immediately.

Q: What exactly does the Glass Window show? Can I stop a request that has already left?

A: The Glass Window shows in real time the five phases of every Chatbot request: the original text, the data found by the privacy filter with the Vault tags, the text actually sent to the model, the exact HTTP or CLI payload (with keys masked) and the raw answer stream. Stop operation halts the request at any moment: the connection to the AI service is closed (or the CLI is terminated with all its processes) and from then on no data is transmitted or received. To make sure nothing leaves without your consent, turn on Review before sending: the request leaves only with Send now. The Glass Window content is not saved anywhere.

Q: Antigravity, Qwen 4 Max, GLM 5.3 or Ollama are greyed out: how do I make them usable?

A: Use the button next to the entry (in the picker at the bottom right or in Settings › AI, keys & Chatbot). For Antigravity, Install CLI installs Antigravity CLI, which uses the account already signed in to Antigravity Desktop (if it is missing, Sign in with Google). Qwen and GLM need a key of the right plan (Qwen4-Max only with the Token Plan; different keys per plan and region): Retrieve configuration links the one already set in another tool without copying it, otherwise enter it with «Key». For a stopped Ollama, LM Studio or Jan, Start; if they are not installed, Install (Ollama on Windows) or the official page; without models, Download a recommended model. The Remote Control and Germano Client have no assistant: it is used on the server computer.

Q: How do I prevent operators from disabling filters (PA profile)?

A: The administrator sets "compliance_mode": "PA" and "lock_settings": true in config.json: the Dashboard then shows a padlock next to the profile and rejects any filter change; the Remote Control and Germano Client show the options greyed out and the server rejects changes (403).

Q: Do redacted files preserve their original typography and tables?

A: Yes. Word, Excel, PowerPoint and OpenDocument files are edited directly in their XML: formatting, images, tables, formulas and macros stay intact and only personal text changes (the tag takes the style of the first part of the replaced data). In PDFs the tags are inserted where the text was removed, with a smaller font size when space is tight.

Q: How do I transfer protected documents and data to a new folder or another PC?

A: Close Germano (so the Vault copy is up to date) and copy extracted/deanonymize_vault.json from the previous directory (required to restore true data in protected files) and optionally config.json with your settings. On launch Germano imports the JSON mappings into its database (deanonymize_vault.db) without losing the existing ones.

14. Developer Guide: Running from GitHub Sources

Il repository ufficiale su GitHub contiene esclusivamente il codice sorgente pulito e gli asset grafici/web, nelle cartelle windows/, linux/ e macos/ (ognuna con germano/ e germano-client/). Per rispettare i limiti dimensionali di Git, i modelli neurali e i runtime binari non sono inclusi nel repository. Gli installer ufficiali, invece, contengono già tutto: per usare Germano non serve nessuno dei passaggi seguenti.

Cosa serve oltre ai sorgenti:
  • Modelli IA (models/): gli 8 modelli (anonimizzazione dei dati personali, NER, OCR, biometria facciale YuNet, firme e targhe, Whisper per l'audio e Qwen3.5 per il Sistema 2), già inclusi e pre-installati negli installer ufficiali di Germano AI (per lo sviluppo dai sorgenti, è sufficiente copiare la cartella models/ dalla directory dell'applicazione installata o estrarla dall'installer) e posizionarla accanto a server.py.
  • Python 3.11 a 64 bit con le librerie di requirements.txt (su Linux torch per CPU dall'indice di PyTorch: --extra-index-url https://download.pytorch.org/whl/cpu). Su Windows PyTorch richiede il ridistribuibile Microsoft Visual C++ 64-bit (vc_redist.x64.exe), le cui librerie sono già incluse negli installer.

Avvio rapido per sviluppatori in 4 passaggi:

# 1. Clona il repository GitHub
git clone https://github.com/germano-ai/germano-ai-standalone.git
cd germano-ai-standalone/windows/germano # oppure linux/germano o macos/germano

# 2. Crea l'ambiente virtuale e installa le librerie
python -m venv venv
# Windows: venv\Scripts\activate | Linux/macOS: source venv/bin/activate
pip install -r requirements.txt

# 3. Copia qui la cartella 'models/' (dall'installazione di Germano AI)

# 4. Avvia l'applicazione nella sua finestra (solo il server: python server.py)
python germano_desktop.py

Gli installer (.exe, .deb, .pkg) si costruiscono con gli script di windows/germano/build/ (costruisci_installer_windows.py, costruisci_deb.py, costruisci_pkg.py), che uniscono i sorgenti, i runtime e le librerie per ogni sistema operativo (dipendenze/) e gli 8 modelli IA (modelli/). Prima di costruire, coerenza_sorgenti.py verifica che i sorgenti Linux e macOS siano identici a quelli Windows; alla fine crea_version_json.py scrive l'indice per download.germano.ai con dimensione e SHA-256 di ogni pacchetto, letti dai file.

The official GitHub repository contains strictly clean source code and web/graphical assets, in the windows/, linux/ and macos/ folders (each with germano/ and germano-client/). To comply with Git size limits, neural models and binary runtimes are not committed to GitHub. The official installers, instead, already contain everything: none of the following steps is needed to use Germano.

What you need besides the sources:
  • AI Models (models/): the 8 local models (PII redaction, NER, OCR, YuNet facial biometrics, signatures and plates, Whisper for audio and Qwen3.5 for System 2), bundled and pre-installed inside the official Germano AI installers (for development from source, simply copy the models/ folder from the installed application directory or extract it from the installer) and place it next to server.py.
  • 64-bit Python 3.11 with the libraries in requirements.txt (on Linux CPU torch from the PyTorch index: --extra-index-url https://download.pytorch.org/whl/cpu). On Windows PyTorch requires the Microsoft Visual C++ 64-bit redistributable (vc_redist.x64.exe), whose libraries are already bundled in the installers.

Quick developer setup in 4 steps:

# 3. Copy the 'models/' folder here (from your Germano AI installation)

# 4. Launch the application in its window (server only: python server.py)

Before building, coerenza_sorgenti.py checks that the Linux and macOS sources are identical to the Windows ones; at the end crea_version_json.py writes the index for download.germano.ai with the size and SHA-256 of every package, read from the files.
