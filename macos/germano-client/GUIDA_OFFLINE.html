1. Introduzione & Modalità Operativa (Standalone, Server, Client, Remote Control)

1. Introduction & Operating Modes (Standalone, Server, Client, Remote Control)

Germano AI è una suite autonoma progettata per proteggere la privacy, eliminare i dati personali sensibili (GDPR Art. 9 e 10) e consentire l'utilizzo sicuro di strumenti di Intelligenza Artificiale Cloud (come ChatGPT, Claude o Google Gemini) e ambienti di sviluppo CLI (Claude Code, OpenAI Codex CLI, Aider, OpenCode, Goose CLI) su qualsiasi computer con Windows 10 o 11, su Windows Server 2019 o successivo e nelle macchine virtuali (oltre che su macOS e Linux).

🛡️
100% Locale, Standalone e Air-Gapped:

Germano AI include un runtime Python 3.11 embedded, tutte le librerie native C++ di sistema e 6 modelli di Intelligenza Artificiale pre-installati. Si installa con un solo file (germano-0.60.exe), che appena si apre chiede i permessi di amministratore (richiesta UAC) per consentire l'accesso dalla rete locale e alla fine apre Germano da solo, e funziona senza alcuna connessione a Internet per elaborare i documenti. Nessun dato personale lascia mai il tuo computer (con il Proxy API all'AI arrivano solo testi già anonimizzati); l'unico collegamento automatico è il controllo degli aggiornamenti, solo quando il PC è connesso e disattivabile (capitolo 13).

Modalità operativa: Standalone, Server, Client

Alla prima apertura della Dashboard una finestra di benvenuto chiede come usare Germano su questo computer. Questa modalità è sempre modificabile in qualsiasi momento nelle Impostazioni (pulsante Impostazioni in alto, oppure Sistema e registro › Rete e modalità operativa) e si applica subito, senza riavviare.

  • 🖥️ Standalone (predefinita): tutto gira al 100% su questo computer, in modo isolato. Germano non cerca server in rete e non risponde ai computer della rete: la Dashboard e il Proxy ascoltano solo su 127.0.0.1.
  • 📡 Server: Germano si mette in ascolto anche sulla rete locale, risponde al rilevamento automatico (UDP 8182) e offre agli altri computer e dispositivi il proprio motore di anonimizzazione, il Proxy e il Remote Control (da qualsiasi browser della rete, vedi i capitoli 2 e 11). Di base l'accesso dalla rete è libero; con la gestione utenti servono utente e password. Le Impostazioni mostrano gli indirizzi da aprire nel browser (http://<IP>:8181/remote). Con l'installer di Windows la regola del firewall (solo reti private e di dominio) è già creata; se esegui Germano dai sorgenti, al primo avvio Windows può chiedere di consentire Python sulle reti private: rispondi Consenti. Per un solo avvio la modalità si può imporre anche con la variabile d'ambiente GERMANO_MODE=server (utile negli script).
  • 🌐 Client: all'avvio del motore Germano cerca in rete un Germano Server (oppure usa l'indirizzo indicato) e gli affida il calcolo dei modelli: questo computer non li carica in memoria. Al server vanno solo i testi e le immagini da analizzare; Vault, etichette, file e ripristino restano su questo computer. Se il server ha la gestione utenti attiva, inserisci utente e password (Germano conserva solo la sessione). Se il server non risponde, o rifiuta l'accesso, nessun dato esce: Proxy e Studio bloccano la richiesta e i documenti restano nella cartella input finché il server torna disponibile (in alternativa si può scegliere di usare il motore locale).
  • Server + Client: le due parti insieme. Un computer che delega il calcolo non condivide però il proprio motore con altri (niente catene).

Il cambio di modalità è possibile solo dal computer stesso, mai dalla rete; con "lock_settings": true l'amministratore la blocca. In config.json la scelta è salvata in operating_mode (standalone, server, client, server+client).

Suggerimenti al passaggio del mouse

Passando il mouse (o spostandosi con il tasto Tab) su pulsanti, cartelle, campi, filtri e indicatori compare una breve spiegazione. I suggerimenti sono attivi per impostazione predefinita e si disattivano nelle Impostazioni, sezione Interfaccia (enable_tooltips).

Caratteristiche principali

Germano AI è una suite completa di anonimizzazione documentale e proxy di privacy con una Dashboard moderna e intuitiva, verificata da test automatici rigorosi.

  • Nuova Dashboard per il lavoro in blocco: grafica più sobria; si aggiungono file o intere cartelle trascinandoli sul riquadro input (o con i pulsanti Seleziona file e Seleziona cartella); i quattro riquadri input, output, processed e failed mostrano in tempo reale, come un file manager, i file di ogni cartella con il suo percorso completo, e un clic apre la cartella in Esplora file. I documenti non elaborati sono elencati con il motivo e si rimettono in coda con un clic; l'elenco si esporta in CSV per Excel (capitolo 2).
  • Remote Control e gestione utenti: in modalità Server qualsiasi dispositivo della rete usa dal browser, senza installare nulla, le AI del server filtrate da Germano (CLI condivise, servizi via API come Meta Muse, Kimi, DeepSeek, Qwen, Mistral, Grok, Perplexity e Gemini, modelli locali con Ollama o LM Studio); accesso libero oppure con utente e password; opzioni di elaborazione per dispositivo, bloccate e in grigio con il profilo PA (capitoli 2 e 11).
  • Endpoint per gli agenti AI: in Modalità Avanzata la scheda Agenti AI e API mostra gli indirizzi del Proxy (formato OpenAI e formato Anthropic) e, per ogni strumento (Claude Code, Codex CLI, Aider, OpenCode, Goose CLI, SDK OpenAI e Anthropic), dove impostarli, con le istruzioni da copiare; seguono gli esempi delle API REST locali (capitolo 12).
  • Aggiornamenti automatici: solo quando Windows segnala che il PC è connesso a Internet, Germano cerca una nuova versione sul server ufficiale (download.germano.ai), scarica il nuovo installer in un solo file e lo avvia al successivo avvio (o subito, con Installa ora e riavvia): l'installer chiude Germano, lo aggiorna e lo riapre. Documenti, Vault e impostazioni non vengono toccati e, se l'installazione non va a buon fine, resta la versione in uso. Si disattiva in Sistema e registro → Aggiornamenti (capitolo 13).
  • Documenti Office intatti: Word, Excel, PowerPoint e OpenDocument vengono modificati direttamente nel loro XML. Grassetti, font, immagini, tabelle, formule e macro restano identici. Vengono anonimizzati anche note a piè di pagina, caselle di testo, commenti e relativi autori, revisioni, note del relatore, grafici, metadati e miniature di anteprima.
  • PDF più sicuri: OCR anche sulle scansioni con timbro digitale (protocollo), oscuramento dei pixel sotto il testo delle scansioni "ricercabili", pagine ruotate gestite correttamente; anonimizzati campi modulo, commenti, segnalibri, metadati e allegati incorporati; le firme digitali PAdES (con nome e codice fiscale del firmatario) vengono rimosse.
  • Proxy API corretto: Lo streaming per Claude Code e Codex (formati Anthropic e OpenAI Responses) è completamente supportato, anche con immagini e PDF allegati; gli argomenti dei tool restano JSON validi e un'analisi a batch con cache rende le conversazioni lunghe molto più veloci.
  • Nuovi formati: RTF nativo senza Word, file firmati .p7m (es. fattura.xml.p7m), JSON, TSV, Markdown, log, codice sorgente, GIF e modelli Office; i .doc/.xls che in realtà sono RTF, DOCX o HTML rinominati vengono riconosciuti senza Office.
  • Riconoscimento più preciso: il modello italiano analizza ora i documenti lunghi per intero (prima si fermava dopo poche righe); RegEx validate per IBAN europei, codici fiscali (anche omocodici o letti male dall'OCR), carte di pagamento, telefoni, targhe e CIE; un nome trovato in un punto viene oscurato in tutto il documento.
  • Affidabilità: il motore si chiude da solo con la finestra di Germano, i file vengono elaborati solo a copia completata, il Vault è protetto da scritture concorrenti, i documenti lunghi hanno fino a 60 minuti (configurabili) e la Dashboard mostra avanzamento e motivo di ogni errore.
  • Sicurezza: l'API locale rifiuta le richieste provenienti da siti web esterni e il motore interno è protetto da token. Nessun dato dei documenti viene inviato in rete: l'unico collegamento automatico è il controllo degli aggiornamenti, solo quando Windows segnala che il PC è connesso a Internet.
  • Per gli amministratori: blocco delle impostazioni per il profilo PA ("lock_settings": true), scelta della precisione del modello (FP32/BF16), anonimizzazione dei nomi dei file, servizio Anthropic configurabile a parte.

Sistemi supportati: Windows 10/11, Windows Server e macchine virtuali

  • Windows 10 e 11 a 64 bit.
  • Windows Server 2019, 2022 e 2025 (Standard e Datacenter), con Esperienza desktop per la finestra di Germano. Windows Server 2019 non include Microsoft Edge: senza Edge (o Chrome) Germano non usa Internet Explorer, che non sa mostrare la Dashboard, ma resta attivo come server senza finestra e indica gli indirizzi da aprire (anche da un altro computer); installando Microsoft Edge torna la sua finestra. Su Server Core, che non ha né Edge né il desktop, si usa la modalità senza finestra (capitolo 11).
  • Macchine virtuali: VMware (ESXi, Workstation), Hyper-V, Proxmox VE (KVM/QEMU), VirtualBox e le istanze cloud (AWS EC2, Azure, Google Compute Engine). Non serve una GPU: tutta la pipeline gira su CPU; il numero di thread si adatta alle vCPU e la precisione al processore (capitolo 9). Per l'accesso dalla rete la VM deve avere una scheda in modalità bridge (o uno switch virtuale esterno): dietro un NAT servono l'inoltro della porta TCP 8181 e l'indirizzo indicato a mano nei client, perché il rilevamento automatico (UDP 8182) non attraversa il NAT.
  • Nessuna installazione esterna: il programma contiene Python 3.11 e le DLL di Microsoft Visual C++ 2015-2022 (vcruntime140.dll, vcruntime140_1.dll, msvcp140.dll, msvcp140_1.dll, msvcp140_2.dll, vcomp140.dll per OpenMP, concrt140.dll e le altre): funziona anche su un Windows Server appena installato, senza ridistribuibili. Le altre DLL usate sono componenti standard di Windows.
  • I dati (Vault, cartelle di lavoro, stato) possono stare su dischi virtuali (vmdk, vhdx, qcow2) come su quelli fisici. Una cartella dati su una condivisione di rete (SMB o NFS) è protetta da un blocco del sistema operativo: un secondo Germano, anche da un altro computer, non può usarla insieme al primo (il Vault non può avere due scrittori).

Germano AI ships with an embedded Python 3.11 runtime, all native Visual C++ runtime libraries, and 6 pre-packaged local AI models. It installs from a single file (germano-0.60.exe), which asks for administrator permission as soon as it opens (UAC prompt) to allow access from the local network and opens Germano by itself at the end, and works with no Internet connection needed to process documents. No personal data ever leaves your machine (with the API Proxy, the AI only receives already anonymized text); the only automatic connection is the update check, only when the PC is online, and it can be turned off (chapter 13).

Operating mode: Standalone, Server, Client

On the first Dashboard launch a welcome dialog asks how to use Germano on this computer. The mode can always be changed at any time in the Settings (the Impostazioni button at the top, or Sistema e registro › Rete e modalità operativa) and applies immediately, without restarting.

  • 🖥️ Standalone (default): everything runs 100% on this computer, isolated. Germano does not search the network for servers and does not answer the computers on the network: the Dashboard and the proxy only listen on 127.0.0.1.
  • 📡 Server: Germano also listens on the local network, answers the auto-discovery (UDP 8182) and offers the other computers and devices its anonymization engine, the proxy and the Remote Control (from any browser on the network, see chapters 2 and 11). By default network access is open; with user management a user name and password are required. The Settings show the addresses to open in the browser (http://<IP>:8181/remote). With the Windows installer the firewall rule (private and domain networks only) is already in place; when running Germano from source, Windows may ask on first start to allow Python on private networks: answer Allow. For a single run the mode can also be forced with the environment variable GERMANO_MODE=server (useful in scripts).
  • 🌐 Client: when the engine starts, Germano looks for a Germano Server on the network (or uses the address entered) and hands it the model computation: this computer does not load the models in memory. Only the texts and images to analyze go to the server; Vault, tags, files and restoration stay on this computer. If the server has user management enabled, enter user name and password (Germano keeps only the session). If the server does not answer, or refuses access, no data leaves: the proxy and the Studio block the request and documents stay in the input folder until the server is back (alternatively you can choose to use the local engine).
  • Server + Client: both parts together. A computer that delegates its computation does not share its own engine with others (no chains).

The mode can only be changed from the computer itself, never from the network; with "lock_settings": true the administrator locks it. In config.json the choice is saved in operating_mode (standalone, server, client, server+client).

Hover tooltips

Hovering with the mouse (or moving with the Tab key) over buttons, folders, fields, filters and indicators shows a short explanation. Tooltips are on by default and can be turned off in the Settings, Interfaccia (interface) section (enable_tooltips).

Main features

Germano AI is a complete document anonymization suite and privacy proxy with a modern, intuitive Dashboard, verified by rigorous automated tests.

  • New Dashboard for batch work: a cleaner look; you add files or whole folders by dragging them onto the input box (or with the Select files and Select folder buttons); the four boxes input, output, processed and failed show in real time, like a file manager, the files of each folder with its full path, and a click opens the folder in File Explorer. Unprocessed documents are listed with the reason and re-queued with one click; the list can be exported to CSV for Excel (chapter 2).
  • Remote Control and user management: in Server mode any device on the network uses from the browser, with nothing to install, the server's AIs filtered by Germano (shared CLIs, services via API such as Meta Muse, Kimi, DeepSeek, Qwen, Mistral, Grok, Perplexity and Gemini, local models with Ollama or LM Studio); open access or user name and password; per-device processing options, locked and greyed out with the PA profile (chapters 2 and 11).
  • Endpoints for AI agents: in Advanced Mode the Agenti AI e API tab shows the Proxy addresses (OpenAI format and Anthropic format) and, for each tool (Claude Code, Codex CLI, Cursor, Antigravity, Windsurf, OpenCode, Continue, Aider, OpenAI and Anthropic SDKs), where to set them, with instructions to copy; examples of the local REST APIs follow (chapter 12).
  • Automatic updates: only when Windows reports that the PC is connected to the Internet, Germano looks for a new version on the official server (download.germano.ai), downloads the new single-file installer and runs it at the next start (or right away, with Installa ora e riavvia): the installer closes Germano, updates it and reopens it. Documents, Vault and settings are not touched and, if the installation fails, the current version stays. It can be turned off in Sistema e registro → Aggiornamenti (chapter 13).
  • Office documents intact: Word, Excel, PowerPoint and OpenDocument files are edited directly in their XML. Bold, fonts, images, tables, formulas and macros stay identical. Footnotes, text boxes, comments and their authors, revisions, speaker notes, charts, metadata and preview thumbnails are anonymized too.
  • Safer PDFs: OCR also on scans with a digital stamp (registry protocol), pixels under the text of "searchable" scans are blacked out, rotated pages are handled correctly; form fields, comments, bookmarks, metadata and embedded attachments are anonymized; PAdES digital signatures (with the signer's name and tax code) are removed.
  • Fixed API Proxy: streaming for Claude Code and Codex (Anthropic and OpenAI Responses formats) is fully supported, also with attached images and PDFs; tool arguments remain valid JSON and batch analysis with caching makes long conversations much faster.
  • New formats: native RTF without Word, signed .p7m files (e.g. fattura.xml.p7m), JSON, TSV, Markdown, logs, source code, GIF and Office templates; .doc/.xls files that are actually renamed RTF, DOCX or HTML are recognized without Office.
  • More accurate recognition: the Italian model now analyzes long documents in full (it used to stop after a few lines); validated RegEx for European IBANs, tax codes (including omocodes or codes misread by OCR), payment cards, phone numbers, license plates and electronic ID cards; a name found in one place is redacted throughout the document.
  • Reliability: the engine shuts down by itself with the Germano window, files are processed only once fully copied, the Vault is protected from concurrent writes, long documents get up to 60 minutes (configurable) and the Dashboard shows the progress and the reason for every error.
  • Security: the local API rejects requests coming from external websites and the internal engine is protected by a token. No document data is sent over the network: the only automatic connection is the update check, only when Windows reports that the PC is connected to the Internet.
  • For administrators: settings lock for the PA profile ("lock_settings": true), choice of the model precision (FP32/BF16), file name anonymization, separately configurable Anthropic service.

Supported systems: Windows 10/11, Windows Server and virtual machines

  • Windows 10 and 11, 64-bit.
  • Windows Server 2019, 2022 and 2025 (Standard and Datacenter), with the Desktop Experience for Germano's window. Windows Server 2019 does not include Microsoft Edge: without Edge (or Chrome) Germano does not use Internet Explorer, which cannot show the Dashboard, but stays active as a server without a window and shows the addresses to open (also from another computer); after installing Microsoft Edge its window is back. On Server Core, which has neither Edge nor the desktop, use the windowless mode (chapter 11).
  • Virtual machines: VMware (ESXi, Workstation), Hyper-V, Proxmox VE (KVM/QEMU), VirtualBox and cloud instances (AWS EC2, Azure, Google Compute Engine). No GPU is needed: the whole pipeline runs on the CPU; the number of threads adapts to the vCPUs and the precision to the processor (chapter 9). For network access the VM needs an adapter in bridged mode (or an external virtual switch): behind NAT you need TCP port 8181 forwarding and the address entered by hand in the clients, because auto-discovery (UDP 8182) does not cross NAT.

The other DLLs used are standard Windows components.

A data folder on a network share (SMB or NFS) is protected by an operating-system lock: a second Germano, even from another computer, cannot use it together with the first one (the Vault cannot have two writers).

2. Basic Guide: Interactive Folders, AI Studio & Web Remote Control

La Modalità Semplice (attiva all'apertura) mostra solo ciò che serve per lavorare: aggiungere i documenti, avviare il motore e ritirare i risultati. Per gli altri controlli scegli Avanzata nel selettore Semplice / Avanzata in alto.

Avviare e arrestare il motore

In alto a destra trovi lo stato del motore e il pulsante principale:

  • Avvia motore: carica i modelli IA locali (servono da qualche decina di secondi a qualche minuto, a seconda del PC). Finché il motore è in pausa non consuma memoria né processore.
  • Arresta motore: ferma il motore e libera la memoria. I documenti in attesa restano nella cartella input e vengono elaborati al successivo avvio.
💡
Avvio automatico: se aggiungi documenti dalla Dashboard o usi Anonimizza testo, il motore si avvia da solo. Se copi i file nella cartella input con Esplora file, compare l'avviso dei documenti in attesa con il pulsante Avvia elaborazione.

Lavorare in blocco, passo per passo

1

Aggiungi i documenti

Trascina file o intere cartelle sul riquadro input della sezione Cartelle di lavoro (dove è scritto «Trascina i file qui nella cartella di input»), oppure usa Seleziona file / Seleziona cartella. Per lotti grandi copia i file direttamente nella cartella input: il suo percorso completo è scritto sopra il riquadro e un clic sul riquadro la apre in Esplora file. La struttura delle sottocartelle viene mantenuta.

2

Segui l'avanzamento

I quattro riquadri si aggiornano in tempo reale: il documento in lavorazione è in cima a input (e nella barra di stato sopra i riquadri, con l'avanzamento del lotto), poi sparisce da input e compare in output (anonimizzato) e in processed (originale), oppure in failed con il motivo. Il numero accanto al nome di ogni riquadro conta i file della cartella. A lotto concluso compare il riepilogo dei documenti elaborati e di quelli non riusciti.

3

Ritira i risultati

Nella tabella Documenti, scheda Pronti, ogni file ha i pulsanti per aprirlo, mostrarlo nella cartella o scaricarne una copia; Apri cartella output apre l'intera cartella dei risultati, con la stessa struttura delle cartelle di partenza.

4

Controlla i non riusciti

La scheda Non riusciti elenca i documenti che non è stato possibile elaborare, con il motivo (es. PDF protetto da password). Risolto il problema, usa Rimetti in coda sul singolo file o Rimetti tutti in coda. Esporta elenco salva la tabella in CSV, apribile con Excel.

Anonimizzare un testo al volo

Nel riquadro «Testo da inviare a un servizio di AI» incolla un messaggio o un estratto e premi Anonimizza testo; con Copia risultato lo incolli in ChatGPT o Claude. Se incolli la risposta dell'AI con etichette come [PERSONA_1], Germano rimette al loro posto i dati originali.

Anonimizza file e Studio AI

In alto nella Dashboard un selettore sceglie fra due modi di lavorare: 📂 Anonimizza file (elaborazione in blocco di documenti) e 🧠 Studio AI.

Studio AI

Scrivi un prompt e allega fino a 12 file: Germano protegge prompt e allegati con i modelli locali e il Vault e ti mostra esattamente il testo protetto che riceverà l'AI, con le etichette (es. [PERSONA_1]) e il numero di dati oscurati. Lo Studio non invia nulla da solo: con «Copia testo protetto» incolli il risultato nell'AI che preferisci; la risposta si ripristina con lo strumento Testo o trascinando il file in Anonimizza file. «Rileva AI» elenca le AI installate sul computer leggendo disco e porte locali (senza avviare programmi né usare la rete). «Configurazione Granulare» apre un pannello laterale con profilo, modelli e categorie. A motore spento non esce alcun dato (compare «Avvia motore»). Le immagini allegate non sono testo: per oscurarle usa Anonimizza file.

Cartelle di lavoro: anteprima come in un file manager

In Anonimizza file la sezione Cartelle di lavoro mostra quattro riquadri, uno per cartella — 📥 input (da elaborare), ✅ output (anonimizzati), 🗂️ processed (originali), ⚠️ failed (non riusciti) — con il percorso completo della cartella sopra ogni riquadro e, dentro, i file che contiene, aggiornati in tempo reale: i file appena arrivati sono evidenziati, quello in elaborazione è in cima a input, quelli non riusciti mostrano il motivo e il pulsante Rimetti in coda. I documenti si trascinano direttamente sul riquadro input («Trascina i file qui nella cartella di input»); un clic su un riquadro o sul suo percorso apre la cartella in Esplora file (Finder su macOS, il file manager su Linux) e sotto i riquadri un collegamento apre il Vault (extracted). Nell'intestazione, le statistiche dal vivo: documenti elaborati/totali del lotto, dati personali oscurati, documenti al minuto, uso di CPU e RAM. Thumbs.db, desktop.ini e i file nascosti non vengono contati come documenti da elaborare.

Interfaccia bilingue (italiano/inglese)

La Dashboard è completamente bilingue. All'avvio sceglie la lingua dal browser (italiano se la lingua inizia per it, altrimenti inglese); le bandierine 🇮🇹 IT / 🇬🇧 EN in alto cambiano lingua all'istante, tooltip compresi, e la scelta viene ricordata (ed è condivisa con questa guida). I messaggi tecnici del Registro attività restano in italiano. Le etichette usate nei documenti (es. [PERSONA]) sono sempre in italiano, in entrambe le lingue dell'interfaccia.

Correzioni di affidabilità

9. Hardware, Soglia IA & Gestione Vault

9. Hardware, AI Threshold & Vault Management

Soglia di Confidenza IA (Cursore di Sicurezza)

Il cursore di sensibilità consente di impostare la soglia minima di certezza dell'Intelligenza Artificiale:

  • 0% (Massima Sicurezza - Profilo PA / GDPR Predefinito): Qualsiasi elemento che presenti anche il minimo dubbio viene oscurato. È la modalità consigliata per la Pubblica Amministrazione e per evitare sanzioni GDPR.
  • Valori intermedi (10% - 50%): Modalità bilanciata adatta a testi commerciali e di marketing per ridurre al minimo i falsi positivi.

Accelerazione Hardware

Germano include 3 modalità di esecuzione selezionabili:

  1. Automatico (Consigliato): usa una scheda NVIDIA (CUDA) se disponibile, altrimenti il processore. Nota: il pacchetto standard include PyTorch per CPU, che funziona su qualsiasi PC senza driver aggiuntivi; l'accelerazione GPU richiede di sostituire PyTorch con una versione CUDA.
  2. Solo CPU: esegue tutti i modelli sul processore centrale (funziona su qualsiasi PC, server o macchina virtuale, senza GPU né driver).
  3. Forza GPU NVIDIA: per installazioni con PyTorch CUDA; in caso di errore della GPU Germano passa comunque alla CPU.

Memoria RAM e Precisione del Modello

Il modello principale (1,5 miliardi di parametri) può essere caricato in due modi:

  • FP32 (veloce): circa 5,3 GB di RAM. Scelto automaticamente con almeno 12 GB di RAM, e anche con meno se ci sono almeno 7 GB liberi e il processore non ha il BF16 nativo.
  • BF16 (leggero): circa 2,7 GB di RAM. Scelto automaticamente quando la memoria non basta per FP32. Sui processori senza BF16 nativo (AVX2: Intel Haswell e Broadwell, Xeon E5 v3/v4, molti host di virtualizzazione) è da 4 a 10 volte più lento (misurato su un i5-4570: 12,4 s contro 1,6 s per blocco di testo); sui processori con AVX-512 o AMX (Xeon Scalable, AMD EPYC Zen 4) la differenza è contenuta.

Se il BF16 non funziona sul processore (operazioni mancanti), Germano passa da solo a FP32, sia all'avvio sia durante l'elaborazione, e lo annota nel registro. Requisiti consigliati: 16 GB di RAM (minimo 8 GB), almeno 4 processori (o vCPU) e 6 GB di spazio libero su disco. La scelta si può forzare in Modalità Avanzata (Sistema e registro → Precisione del modello principale) e vale dal successivo avvio del motore.

Processori, thread e macchine virtuali

Germano usa i processori che il sistema concede al programma (le vCPU di una macchina virtuale, o l'affinità impostata dall'amministratore): tutti fino a 2, poi uno lasciato libero per il server web, il sistema e gli altri servizi della macchina (su 4 core costa circa il 2% di velocità), al massimo 16. Il numero si cambia con "cpu_threads" in config.json (0 = automatico) o con la variabile GERMANO_CPU_THREADS; un OMP_NUM_THREADS già impostato dall'amministratore viene rispettato. Il registro del motore (daemon.log) e il suggerimento sullo stato del motore mostrano processori, thread, precisione, presenza del BF16 nativo e l'eventuale macchina virtuale (VMware, Hyper-V, KVM/Proxmox, VirtualBox, cloud). Non serve nessuna GPU: tutta la pipeline (modelli di testo, OCR, volti, firme, targhe) gira su CPU.

Gestione del Vault delle Corrispondenze

La tabella delle corrispondenze risiede localmente in extracted/deanonymize_vault.json. In Modalità Avanzata, scheda Sistema e registro, riquadro Archivio delle corrispondenze: Mostra visualizza tutte le etichette attive, Svuota azzera le corrispondenze per iniziare una nuova sessione pulita (i documenti protetti in precedenza non potranno più essere ripristinati).

🔐
Il Vault contiene i dati veri in chiaro: conserva la cartella Documenti\Germano AI su un disco protetto (es. BitLocker) e con accesso riservato. Se disattivi l'interruttore Ripristino automatico dei dati originali, Germano usa etichette non numerate (es. [PERSONA]) e non salva più i dati nel Vault: l'anonimizzazione diventa irreversibile.

AI Confidence Threshold (Safety Slider)

The sensitivity slider defines the minimum statistical probability threshold required for AI redactions:

  • 0% (Maximum Safety - Default GDPR / Public Administration Profile): Redacts any span that raises even the slightest suspicion. Recommended for strict compliance scenarios.
  • Balanced Values (10% - 50%): Optimal for commercial and marketing copy to eliminate occasional false positives.

Hardware Acceleration Modes

Germano supports 3 selectable compute execution backends:

  1. Automatic (Recommended): uses an NVIDIA (CUDA) GPU when available, otherwise the CPU. Note: the standard package ships the CPU build of PyTorch, which works on any PC without extra drivers; GPU acceleration requires replacing PyTorch with a CUDA build.
  2. CPU Only: executes models exclusively on the CPU (works on any PC, server or virtual machine, with no GPU or drivers).
  3. Force NVIDIA GPU: for installations with CUDA PyTorch; on GPU errors Germano still falls back to the CPU.

RAM and Model Precision

The main model (1.5 billion parameters) can be loaded in two ways:

  • FP32 (fast): about 5.3 GB of RAM. Selected automatically with at least 12 GB of RAM, and also with less when at least 7 GB are free and the CPU has no native BF16.
  • BF16 (light): about 2.7 GB of RAM. Selected automatically when memory is not enough for FP32. On CPUs without native BF16 (AVX2: Intel Haswell and Broadwell, Xeon E5 v3/v4, many virtualization hosts) it is 4 to 10 times slower (measured on an i5-4570: 12.4 s versus 1.6 s per text block); on CPUs with AVX-512 or AMX (Xeon Scalable, AMD EPYC Zen 4) the difference is small.

If BF16 does not work on the CPU (missing operations), Germano switches to FP32 by itself, both at startup and during processing, and records it in the log. Recommended: 16 GB of RAM (8 GB minimum), at least 4 processors (or vCPUs) and 6 GB of free disk space. The choice can be forced in Advanced Mode (Sistema e registro → Precisione del modello principale, main model precision) and applies from the next engine start.

Processors, threads and virtual machines

Germano uses the processors the system grants to the program (the vCPUs of a virtual machine, or the affinity set by the administrator): all of them up to 2, then one is left free for the web server, the system and the other services of the machine (on 4 cores it costs about 2% of speed), at most 16. The number is changed with "cpu_threads" in config.json (0 = automatic) or with the GERMANO_CPU_THREADS variable; an OMP_NUM_THREADS already set by the administrator is honored. The engine log (daemon.log) and the engine status tooltip show processors, threads, precision, native BF16 and the virtual machine, if any (VMware, Hyper-V, KVM/Proxmox, VirtualBox, cloud). No GPU is needed: the whole pipeline (text models, OCR, faces, signatures, plates) runs on the CPU.

In Advanced Mode, Sistema e registro tab, Archivio delle corrispondenze (mapping archive) box: Mostra (Show) displays the current associations, Svuota (Clear) purges them to start a clean session (previously protected documents can no longer be restored).

If you turn off the Ripristino automatico dei dati originali switch, Germano uses non-numbered tags (e.g. [PERSONA]) and does not store data in the Vault anymore: anonymization becomes irreversible.

1. Anonimizzazione Testo (POST /api/v1/anonymize_text)

Anonimizza una stringa di testo arbitraria restituendo il testo bonificato e l'elenco delle entità rilevate. Se il testo contiene etichette del Vault (es. una risposta dell'AI) e lo switch di ripristino è attivo, viene invece restituito con i dati veri e il campo "auto_restored": true; per forzare comunque l'anonimizzazione invia "force_anonymize": true.

cURL Request 
curl -X POST http://127.0.0.1:8181/api/v1/anonymize_text   -H "Content-Type: application/json"   -d '{
    "text": "Il contratto è firmato da Mario Rossi, CF RSSMRA80A01H501U residente in Via Roma 10 a Milano.",
    "force_anonymize": true
  }'
JSON Response (200 OK) 
{
  "anonymized": "Il contratto è firmato da [PERSONA_1], CF [COD.FISCALE/P.IVA_1] residente in [INDIRIZZO_1].",
  "extracted_data": [
    { "word": "Mario Rossi", "label": "[PERSONA_1]", "entity": "private_person", "score": 0.998 },
    { "word": "RSSMRA80A01H501U", "label": "[COD.FISCALE/P.IVA_1]", "entity": "cf_iva", "score": 1.0 },

cURL Request 
curl -X POST http://127.0.0.1:8181/api/v1/deanonymize_text   -H "Content-Type: application/json"   -d '{

3. Anonimizzazione File Singolo (POST /api/v1/anonymize)

Invia un file multipart/form-data e riceve direttamente il file bonificato nel formato originale (per i .p7m il documento interno). La risposta arriva a elaborazione completata, anche per documenti lunghi; il report di audit viene salvato in extracted/api/. Se il file contiene etichette del Vault viene invece restituito con i dati veri ripristinati. Codici di errore: 503 motore non avviato, 415 formato non supportato.

cURL Request 
curl -X POST http://127.0.0.1:8181/api/v1/anonymize   -F "file=@contratto_riservato.docx"   --output "contratto_protetto.docx"

Fornisce lo stato operativo (running, loading_models, stopped, error con il relativo messaggio), il conteggio dei file nelle cartelle, l'avanzamento del documento in lavorazione, il profilo attivo e l'uso di CPU e RAM.

cURL Request 
curl -X GET http://127.0.0.1:8181/api/status

5. Ripristino Dati Veri in un File (POST /api/v1/deanonymize_file)

Riceve uno o più file restituiti dall'AI (campo files o file) e rimette i dati veri al posto delle etichette del Vault, senza usare il motore IA. I file ripristinati vengono salvati in output/ con il prefisso ripristinato_; con ?raw=1 e un solo file la risposta è direttamente il file.

cURL Request 
curl -X POST "http://127.0.0.1:8181/api/v1/deanonymize_file?raw=1"   -F "file=@risposta_ai.docx"   --output "risposta_con_dati_veri.docx"

⚡
Come Funziona il Proxy:

Gli editor o agenti IA (come Google Antigravity, OpenAI Codex CLI, Cursor, Windsurf, Claude Code) indirizzano le loro chiamate API verso http://127.0.0.1:8181/v1 invece che direttamente verso il cloud. Germano intercetta la chiamata in uscita, anonimizza al volo prompt, messaggi, immagini e argomenti delle funzioni (`tool_calls`), inoltra la richiesta al provider prescelto e, quando la risposta torna indietro, rimette automaticamente i dati veri al loro posto prima di passarla all'editor!

Supporto Streaming SSE con `StreamTagBuffer`

Nelle risposte in streaming (Server-Sent Events), i token arrivano spezzati frammento per frammento. Se un modello cloud restituisce un tag suddiviso in più token (es. [PER + SONA_1]), il buffer intelligente StreamTagBuffer di Germano trattiene temporaneamente i caratteri finché il tag non è completo, lo de-anonimizza al volo e rilascia immediatamente il testo originale senza ritardi evidenti.

Supporto Chiamate Funzione & Scrittura File (`tool_calls`)

Quando Google Antigravity o Codex invocano strumenti come write_file o edit_file, Germano de-anonimizza ricorsivamente la stringa JSON contenuta in function.arguments (e in input_json_delta per Claude), con l'escape JSON corretto: il file che l'agente scrive sul disco conterrà sempre i dati reali corretti senza alcuna etichetta residua.

Cosa viene anonimizzato e cosa viene bloccato

  • Anonimizzati: messaggi, istruzioni di sistema, argomenti e risultati dei tool, riassunti del ragionamento, immagini (image_url, input_image, blocchi image di Claude) e documenti allegati (PDF, Word, Excel, testo) nei formati OpenAI, Responses e Anthropic.
  • Lasciati intatti: i blocchi thinking firmati di Claude (sono generati dall'AI a partire dal testo già anonimo e una modifica invaliderebbe la firma), definizioni dei tool e parametri tecnici.
  • Bloccati (fail-safe): audio (la voce è un dato biometrico) e allegati di formato sconosciuto; se il motore IA non è attivo la richiesta non viene inoltrata.
  • Sono inoltrati gli header necessari (Authorization, x-api-key, anthropic-version, anthropic-beta...) e i parametri dell'indirizzo (es. ?beta=true); è supportato anche /v1/messages/count_tokens.
  • Le connessioni verso il servizio IA usano il proxy di sistema e i certificati di Windows (utile nelle reti aziendali con ispezione TLS).
  • La mappa delle sostituzioni di ogni richiesta viene registrata in extracted/proxy_sessions/AAAA-MM-GG.jsonl (disattivabile con "save_proxy_logs": false in config.json).

Prestazioni: la prima richiesta di una conversazione lunga può richiedere alcune decine di secondi su CPU; i messaggi già analizzati vengono memorizzati, quindi le richieste successive analizzano solo il testo nuovo.

  • Ripristino limitato alla richiesta: per le richieste dalla rete e per le AI condivise il server rimette nella risposta solo i dati della stessa richiesta, mai altri dati del Vault; un'etichetta di un altro documento resta un'etichetta. Dal computer del server il Proxy continua a usare l'intero Vault, come prima.
  • Le AI condivise sono eseguite sul server senza strumenti: nessuna AI può leggere file o eseguire comandi sul server per conto dei client.
  • In rete locale il collegamento è HTTP, quindi non cifrato: usa il Remote Control su reti fidate (la rete dell'ufficio, non una Wi-Fi pubblica) e, se serve la cifratura, metti davanti al server un proxy HTTPS.

Germano AI includes an embedded Bidirectional Transparent Proxy compliant with the OpenAI standard (`/v1/chat/completions`), Anthropic standard (`/v1/messages`), and Responses API (`/v1/responses`).

⚡
How the Proxy Operates:

AI editors and coding harnesses (such as Google Antigravity, OpenAI Codex CLI, Cursor, Windsurf, Claude Code) point their API requests to http://127.0.0.1:8181/v1 rather than direct cloud endpoints. Germano intercepts outgoing traffic, redacts on the fly prompts, system instructions, images, and function arguments (`tool_calls`), forwards the clean request to OpenAI/Anthropic, and when the stream returns, transparently re-injects real data before handing the response back to your editor!

SSE Streaming via `StreamTagBuffer`

In streaming completions (Server-Sent Events), tokens arrive fragmented across tiny chunks. If an LLM emits a tag split across chunks (e.g. [PER + SONA_1]), Germano's StreamTagBuffer buffers fragments until the bracket closes, queries the local vault, and emits the real restored word without perceptible latency.

Native Tool Calls & File Editing (`tool_calls`)

When autonomous agents like Google Antigravity or Codex invoke file creation or patching tools (`write_file`, `edit_file`), Germano recursively de-anonymizes the JSON string within function.arguments (and input_json_delta for Claude) with correct JSON escaping. As a result, code or documents written to disk by the AI will always feature the authentic real data with zero leftover placeholder tags.

What is anonymized and what is blocked

  • Anonymized: messages, system instructions, tool arguments and results, reasoning summaries, images (image_url, input_image, Claude image blocks) and attached documents (PDF, Word, Excel, text) in the OpenAI, Responses and Anthropic formats.
  • Left untouched: Claude's signed thinking blocks (generated by the AI from already anonymized text; any change would invalidate the signature), tool definitions and technical parameters.
  • Blocked (fail-safe): audio (voice is biometric data) and attachments of unknown type; if the AI engine is not running the request is never forwarded.
  • Required headers are forwarded (Authorization, x-api-key, anthropic-version, anthropic-beta...) together with URL parameters (e.g. ?beta=true); /v1/messages/count_tokens is supported too.
  • Connections to the AI service use the system proxy and the Windows certificate store (useful on corporate networks with TLS inspection).
  • The replacement map of each request is logged to extracted/proxy_sessions/YYYY-MM-DD.jsonl (can be disabled with "save_proxy_logs": false in config.json).

Performance: the first request of a long conversation may take tens of seconds on CPU; already analyzed messages are cached, so following requests only analyze new text.

Fail-safe

Before sending any data the Client checks — without sending any personal data — that a real Germano Server answers at the address, that access is allowed (open, or a valid session) and that the engine is ready; otherwise it sends nothing and explains why. It always connects to the server directly, never through a system or corporate proxy. By default network access is open: anyone connected to the local network can use the engine, the Proxy and the Remote Control. To restrict it, in the server's Dashboard open Settings › Network access › User management, add one or more users (name with letters, digits and . _ @ -; password of at least 8 characters) and enable «Require user name and password for network access». From then on:

  • the browser shows the sign-in screen; the session stays in a protected cookie (HttpOnly, SameSite=Strict) and lasts 30 days from the last use;
  • Germano Client signs in with client login --user mario (the password is typed without being shown) or from its panel, and keeps only the session, never the password;
  • CLIs and SDKs connected to the Proxy use the token created in Connect;
  • requests without valid access get 401; after 5 wrong attempts in 10 minutes the address is blocked for 10 minutes (429).

Passwords are stored in config.json only as a PBKDF2-SHA256 hash (600,000 iterations, random salt), sessions only as a SHA-256 hash. Changing a password closes that user's sessions; turning user management off or on closes them all; deleting the last user turns user management off. From the server computer (127.0.0.1) access never needs credentials and only from there are users, mode and server settings managed; with "lock_settings": true user management is locked too.

Network access security

  • Restoration limited to the request: for network requests and for the shared AIs the server puts back into the answer only the data of the same request, never other Vault data; a tag of another document stays a tag. From the server computer the Proxy keeps using the whole Vault, as before.
  • The shared AIs run on the server without tools: no AI can read files or run commands on the server on behalf of the clients.
  • On the local network the connection is HTTP, therefore not encrypted: use the Remote Control on trusted networks (the office network, not a public Wi-Fi) and, if encryption is needed, put an HTTPS proxy in front of the server.
  • The server's Vault (extracted/deanonymize_vault.json) is not encrypted: protect access to the server computer.

13. FAQ & Troubleshooting

D: Germano AI invia qualcosa su Internet?

R: Nessun dato dei documenti. L'anonimizzazione di documenti e testi avviene interamente sul PC: i 6 modelli IA risiedono nella cartella models/ e la telemetria delle librerie è disattivata. Le sole connessioni sono il controllo degli aggiornamenti, solo se Windows segnala che il PC è connesso a Internet (guarda nella cartella ufficiale di download download.germano.ai se c'è una versione più recente e, se serve, la scarica: vedi la domanda sugli aggiornamenti), e il Proxy API, solo se lo usi, che inoltra all'AI scelta da te le richieste già anonimizzate.

D: Quanta memoria serve?

R: Consigliati 16 GB di RAM (minimo 8 GB). Con meno di 12 GB Germano usa comunque la versione veloce (FP32) se ci sono almeno 7 GB liberi; altrimenti carica il modello principale in versione leggera (BF16): funziona, ma sui processori senza BF16 nativo l'analisi del testo è da 4 a 10 volte più lenta. In una macchina virtuale assegna almeno 12 GB di RAM e 4 vCPU. Vedi il capitolo 9.

D: Germano funziona su Windows Server o in una macchina virtuale?

R: Sì. Windows Server 2019, 2022 e 2025 e le macchine virtuali VMware, Hyper-V, Proxmox VE, VirtualBox e cloud sono supportati, senza GPU e senza installare altro (le DLL di Visual C++ sono incluse). Su Windows Server 2019, che non ha Microsoft Edge, Germano resta attivo come server senza finestra e indica gli indirizzi da aprire; per avviarlo senza finestra fin dall'inizio, anche all'accensione del server: Germano.exe --no-browser --mode=server (capitolo 11).

D: Dagli altri computer il Remote Control non si apre

R: Controlla le Impostazioni del server (Accesso dalla rete): se la scheda di rete è classificata come Pubblica, se la regola del firewall manca o se i criteri di gruppo ignorano le regole locali, la Dashboard lo dice con il comando per correggerlo. In una macchina virtuale con rete NAT serve l'inoltro della porta TCP 8181 (oppure una scheda in modalità bridge) e l'indirizzo va indicato a mano nei client.

D: Il motore non parte o compare un messaggio rosso di errore

R: Il messaggio in alto nella Dashboard indica la causa; il dettaglio completo è nel file daemon.log nella cartella Documenti\Germano AI. Su alcuni PC appena installati la funzione di Windows Smart App Control o l'antivirus possono bloccare i componenti IA: Germano lo segnala tempestivamente all'avvio.

D: Cosa succede se il programma indica che la porta 8181 è occupata?

R: Se Germano è già aperto, un nuovo avvio di Germano si apre semplicemente la Dashboard esistente. Se la porta è usata da un altro programma, chiudilo oppure imposta un'altra porta in config.json (es. "port": 8010) e aggiorna di conseguenza l'indirizzo del Proxy negli editor.

D: Perché vedo l'avviso «Sono rimasti aperti ... processi del motore»?

R: Il motore IA si chiude da solo quando chiudi la finestra di Germano; l'avviso (visibile in Modalità Avanzata) può comparire solo dopo un arresto anomalo del PC. Basta cliccare Chiudi processi secondari nell'avviso in cima alla pagina.

D: Perché un file .doc o .ppt finisce tra i «Non riusciti»?

R: I vecchi formati binari di Office si possono convertire solo con Microsoft Office o LibreOffice installati. Su un PC senza Office salva il documento come .docx/.pptx, oppure installa LibreOffice: Germano lo usa automaticamente. Il motivo esatto di ogni errore è indicato nella scheda Non riusciti; risolto il problema, usa Rimetti in coda.

D: Come funzionano gli aggiornamenti automatici?

R: Circa 20 secondi dopo l'avvio e poi periodicamente, solo se il sistema segnala che il PC è connesso a Internet, Germano contatta direttamente il server ufficiale https://download.germano.ai per verificare la presenza di una nuova versione dell'installer. Se presente, scarica dal server ufficiale il nuovo installer in un solo file (es. germano-0.61.exe) e lo avvia al successivo avvio di Germano, oppure subito con Installa ora e riavvia nella Dashboard: l'installer chiude Germano, lo aggiorna e lo riapre da solo. Se un aggiornamento non va a buon fine resta la versione in uso e non viene riprovato a ogni avvio: si riprova dalla Dashboard. Cartelle di lavoro, Vault e config.json nella cartella Documenti/Germano AI non vengono toccati. Su un PC isolato o offline non avviene alcun tentativo di connessione.

Le opzioni sono in Modalità Avanzata, Sistema e registro → Aggiornamenti: Controlla le nuove versioni quando il computer è connesso a Internet ("check_updates" in config.json) e Scarica automaticamente gli aggiornamenti ("auto_update"; se spenta, Germano si limita a segnalare la nuova versione). Controlla ora esegue subito un controllo.

D: Come impedisco agli operatori di disattivare i filtri (Profilo PA)?

R: L'amministratore imposta in config.json i valori "compliance_mode": "PA" e "lock_settings": true: da quel momento la Dashboard mostra il lucchetto 🔒 accanto al profilo e rifiuta ogni modifica dei filtri (resta possibile solo il cambio tra Modalità Semplice e Avanzata).

D: I file protetti mantengono la grafica e i font originali?

R: Sì. Word, Excel, PowerPoint e OpenDocument vengono modificati direttamente nel loro XML: formattazione, immagini, tabelle, formule e macro restano intatte e cambia solo il testo personale (l'etichetta prende lo stile della prima parte del dato sostituito). Nei PDF le etichette vengono inserite al posto del testo rimosso, con un corpo ridotto se lo spazio è stretto.

D: Come trasferisco documenti e dati protetti in una nuova cartella o su un altro PC?

R: Copia dalla cartella precedente il file extracted/deanonymize_vault.json (indispensabile per ripristinare i dati reali nei documenti protetti) e, facoltativamente, config.json con le tue preferenze. All'avvio di Germano, l'applicazione caricherà automaticamente il Vault.

Q: Does Germano AI transmit any data over the Internet?

A: No document data. Document and text anonymization runs entirely on the PC: all 6 AI models live in models/ and library telemetry is disabled. The only connections are the update check, only when Windows reports that the PC is connected to the Internet (it looks in the official download folder download.germano.ai for a newer version and, if needed, downloads it: see the question about updates), and the API Proxy, only if you use it, which forwards already anonymized requests to the AI service you chose.

Q: How much memory is needed?

A: 16 GB of RAM recommended (8 GB minimum). With less than 12 GB Germano still uses the fast version (FP32) when at least 7 GB are free; otherwise it loads the main model in its light version (BF16): it works, but on CPUs without native BF16 text analysis is 4 to 10 times slower. In a virtual machine assign at least 12 GB of RAM and 4 vCPUs. See chapter 9.

Q: Does Germano work on Windows Server or in a virtual machine?

A: Yes. Windows Server 2019, 2022 and 2025 and VMware, Hyper-V, Proxmox VE, VirtualBox and cloud virtual machines are supported, with no GPU and nothing else to install (the Visual C++ DLLs are included). On Windows Server 2019, which has no Microsoft Edge, Germano stays active as a server without a window and shows the addresses to open; to start it without a window from the beginning, also when the server boots: Germano.exe --no-browser --mode=server (chapter 11).

Q: The Remote Control does not open from the other computers

A: Check the server Settings (Network access): if the network adapter is classified as Public, if the firewall rule is missing or if Group Policy ignores local rules, the Dashboard says so with the command to fix it. In a virtual machine with NAT networking you need TCP port 8181 forwarding (or a bridged adapter) and the address must be entered by hand in the clients.

Q: The engine does not start or a red error message appears

A: The message at the top of the Dashboard shows the cause; full details are in daemon.log in the Documents\Germano AI folder. On some freshly installed PCs, Windows Smart App Control or the antivirus may block the AI components: Germano promptly reports it at startup.

Q: What if port 8181 is reported in use?

A: If Germano is already open, launching Germano again simply opens the existing Dashboard. If another program uses the port, close it or set a different port in config.json (e.g. "port": 8010) and update the Proxy address in your editors.

Q: Why do I see the «Sono rimasti aperti ... processi del motore» (engine processes left open) notice?

A: The AI engine stops automatically when you close the Germano window; the notice (shown in Advanced Mode) can only appear after an abnormal shutdown of the PC. Simply click Chiudi processi secondari (Close orphaned processes) in the notice at the top of the page.

Q: Why does a .doc or .ppt file end up among the «Non riusciti» (failed)?

A: Legacy binary Office formats can only be converted with Microsoft Office or LibreOffice installed. On a PC without Office, save the document as .docx/.pptx, or install LibreOffice: Germano uses it automatically. The exact reason of each failure is shown in the Non riusciti tab; once the problem is solved, use Rimetti in coda (Queue again).

Q: How do automatic updates work?

A: About 20 seconds after startup and then periodically, only when the system reports that the PC is connected to the Internet, Germano contacts the official server https://download.germano.ai directly to check for a newer installer version. If available, it downloads the new single-file installer (e.g. germano-0.61.exe) from the official server and runs it at the next start of Germano, or immediately via Installa ora e riavvia (Install now and restart) in the Dashboard: the installer closes Germano, updates it and reopens it by itself. If an update fails, the version in use is kept and it is not retried at every start: you can retry from the Dashboard. Working folders, Vault, and config.json in Documents/Germano AI remain completely untouched. On a disconnected or offline PC no connection attempt is made.

The options are in Advanced Mode, Sistema e registro → Aggiornamenti: check for new versions when the computer is online ("check_updates" in config.json) and download updates automatically ("auto_update"; when off, Germano only reports the new version). Controlla ora (Check now) runs a check immediately.

Q: How do I prevent operators from disabling filters (PA profile)?

A: The administrator sets "compliance_mode": "PA" and "lock_settings": true in config.json: the Dashboard then shows a 🔒 next to the profile and rejects any filter change (only switching between Simple and Advanced Mode remains possible).

Q: Do redacted files preserve their original typography and tables?

A: Yes. Word, Excel, PowerPoint and OpenDocument files are edited directly in their XML: formatting, images, tables, formulas and macros stay intact and only personal text changes (the tag takes the style of the first part of the replaced data). In PDFs the tags are inserted where the text was removed, with a smaller font size when space is tight.

Q: How do I transfer protected documents and data to a new folder or another PC?

A: Copy extracted/deanonymize_vault.json from the previous directory (required to restore true data in protected files) and optionally config.json with your settings. On launch, Germano automatically loads the Vault.

14. Developer Guide: Running from GitHub Sources

Il repository ufficiale su GitHub contiene esclusivamente il codice sorgente pulito e gli asset grafici/web, nelle cartelle windows/, linux/ e macos/ (ognuna con germano/ e germano-client/). Per rispettare i limiti dimensionali di Git, i modelli neurali e i runtime binari non sono inclusi nel repository. Gli installer ufficiali, invece, contengono già tutto: per usare Germano non serve nessuno dei passaggi seguenti.

📦
Cosa serve oltre ai sorgenti:
  • Modelli IA (models/): i 6 modelli per l'anonimizzazione dei dati personali, OCR, NER e biometria facciale YuNet, già inclusi e pre-installati negli installer ufficiali di Germano AI (per lo sviluppo dai sorgenti, è sufficiente copiare la cartella models/ dalla directory dell'applicazione installata o estrarla dall'installer) e posizionarla accanto a server.py.
  • Python 3.11 a 64 bit con le librerie di requirements.txt (su Linux torch per CPU dall'indice di PyTorch: --extra-index-url https://download.pytorch.org/whl/cpu). Su Windows PyTorch richiede il ridistribuibile Microsoft Visual C++ 64-bit (vc_redist.x64.exe), le cui librerie sono già incluse negli installer.

Avvio rapido per sviluppatori in 4 passaggi:

# 1. Clona il repository GitHub
git clone https://github.com/germano-ai/germano-ai-standalone.git
cd germano-ai-standalone/windows/germano  # oppure linux/germano o macos/germano

# 2. Crea l'ambiente virtuale e installa le librerie
python -m venv venv
# Windows: venv\Scripts\activate | Linux/macOS: source venv/bin/activate
pip install -r requirements.txt

# 3. Copia qui la cartella 'models/' (dall'installazione di Germano AI)

# 4. Avvia l'applicazione nella sua finestra (solo il server: python server.py)
python germano_desktop.py

Gli installer (.exe, .deb, .pkg) si costruiscono con gli script di windows/germano/build/ (costruisci_installer_windows.py, costruisci_deb.py, costruisci_pkg.py), che uniscono i sorgenti, i runtime e le librerie per ogni sistema operativo (dipendenze/) e i 6 modelli IA (models/).

The official GitHub repository contains strictly clean source code and web/graphical assets, in the windows/, linux/ and macos/ folders (each with germano/ and germano-client/). To comply with Git size limits, neural models and binary runtimes are not committed to GitHub. The official installers, instead, already contain everything: none of the following steps is needed to use Germano.

📦
What you need besides the sources:
  • AI Models (models/): the 6 local models for PII redaction, OCR, NER and YuNet facial biometrics, bundled and pre-installed inside the official Germano AI installers (for development from source, simply copy the models/ folder from the installed application directory or extract it from the installer) and place it next to server.py.
